## 1. 调研背景与目标

**背景**：用户在 OB 知识库中长期运营一套由 AI Agent（Hermes）搭建的英语自学体系，该体系以纯笔记 + Agent 对话的方式运转，方法论已被真实学习数据验证。现要求基于该体系，规划并开发一套**可供用户实际上线体验**的英语自学系统（Web 应用），作为作品集项目「词汇生长」。

**调研目标**：
1. 摸清原系统能力边界（词汇、听说、阅读、练习各模块）
2. 提炼已验证方法论（产品化的灵魂）
3. 盘点可复用数据资产（种子数据）
4. 识别原系统局限（产品化的机会点）

**调研方法**：全量阅读系统内 25+ 个 markdown 文件；统计词汇数据规模；对照同级已上线作品集项目「英语开口练」的工程与文档模式。

## 3. 能力清单：原系统已具备什么

### 3.1 词汇模块（核心，最活跃）

| 能力 | 实现方式 | 数据规模 |
|:--|:--|:--|
| 主动词汇库 | markdown 表格：`#/词/造句状态/遗忘深度/备注` | **66 词条**（真实学习数据） |
| 遗忘深度标记 | 三级：🟢0-1层 / 🟡2-3层 / 🔴4层+（复习时第几层提示才想起） | 全量标注 |
| 造句状态 | ⬜待造句 / ✅已造句，附造句记录表（用户原句+纠正内容） | 2条完整记录 |
| 薄弱词清单 | 独立清单 + 四步攻克法（词根拆解/造3句/记忆锚点/连续2次🟢移出） | 规则已定，**流转未自动化** |
| 地道说法库 | 「你想说X → 老外会说Y」按场景分组的语块库 + 来源追踪 | **13 语块**（4场景） |
| 发音听读 | 40 个美式发音 mp3 内联播放器 | 40/66 词覆盖 |

### 3.2 听说模块

- **听力**：双资源每日轮换（Extra English 第4集 ↔ Let's Talk in English 第3集）+ 影子跟读法（升级版：跟读后自造一句）。
- **口语**：每天 15 分钟+ 与老外真实对话；录音复盘法（语音备忘录）；4R 激活循环（限时提取/改写/复用/记录）。
- 立场声明（产品基因）：**想说的欲望 + 敢说的勇气 > 输入积累**；先开口，边聊边补。

### 3.3 阅读模块

- 双资源轮换：牛津书虫入门级（进行到第20篇）↔ 跟美国学生同步练阅读（第3篇）。
- 方法：沉浸式看懂为主，不抠语法；轮换防腻。

### 3.4 练习与复习机制（无算法，纯对话驱动）

**词汇生长系统 v3 工作流**：
```
用户发词 → 判定高频（OPD3词频）→ 语块教学（简单英语释义+发音）
  → 沉淀三库（日志+词汇库+说法库）
  → 触发复习（抽5旧词，优先未造句）
  → 中译英造句 → Agent纠正（语法/搭配/用词/地道四分类）→ 给"老外会说"版本
  → 分层抢救（6级提示）→ 遗忘深度标记 → 隔天巩固 → 当天用掉
```

- **分层抢救六层提示**：硬想30秒 → 词性 → 词义 → 首字母 → 长度 → 场景半句 → 答案。
- **当天用掉铁律**：新句型当天必须在真实对话中用≥1次。
- **新词上限铁律**：待复习>30 即锁定新词，防僵尸词积累。

## 4. 方法论提炼（产品化的灵魂，13 条已验证方法）

产品化时全部继承为产品逻辑，重点 8 条：

1. **识别≠生产**：选择题训练识别，开口需要生产（2-3秒反应窗口）→ 产品练习必须以「产出型题型」为主（造句、说词、拼写），不是选择题。
2. **当天用掉**：新词当天用≥1次，用出来一次比读十遍管用 → 产品要有「今天用掉」的输出闭环与提醒。
3. **被动→主动转化**：问题不是词汇量而是转化率；给旧词装句型骨架 → 词卡必须带语块/句型，不是孤立释义。
4. **词群学习法**：同一故事/场景的词成串学，大脑有故事锚点 → 新词学习按「词群/故事包」组织（如海洋探险11词、登山4词）。
5. **简单英语解释法**：每词配小孩能懂的英文释义，避免中文翻译桥 → 词卡字段设计：simple English definition 优先。
6. **分层抢救**：想不起来的那几秒是大脑加固记忆的时刻；能自己想起来永远比看答案牢 → 复习交互按6级提示逐层解锁。
7. **遗忘是数据不是失败**：遗忘深度映射复习强度（🟢隔天/🟡当天+隔天/🔴进薄弱清单）→ 用遗忘深度做调度依据（SRS-lite）。
8. **语块优先**：语言是语块不是单词；地道说法库积累「你想说X→老外说Y」答案库存 → 独立语块库模块。

其余 5 条：破-立内容结构、沉浸式阅读、证据驱动日志（只记真实发生的学习）、三环教学法（学→复→用）、库存积累法。

## 6. 原系统局限 = 新系统产品化机会

| # | 局限 | 产品化机会 |
|:--|:--|:--|
| 1 | 复习全靠 Agent 对话触发，无调度算法 | 遗忘深度驱动的 SRS-lite 排程引擎 |
| 2 | 三库流转（🔴→薄弱清单、连续2次🟢→移出）写在纸面未执行 | 自动化流转状态机 |
| 3 | 分层抢救、造句纠正全在对话里，无独立练习界面 | 分层抢救交互 + 造句工坊 + 老外版本对照 |
| 4 | 66词表头写"22词"，音频覆盖40/68——数据一致性靠人肉 | 单一数据源 + 自动统计 |
| 5 | 曾发生 cron 重复推送、脚本静默丢 44 词事故 | 前端本地存储 + 数据导入导出（可备份） |
| 6 | 无量化看板（仅词数里程碑） | 词汇生长曲线 / 造句率 / 待复习数 / 连续天数 |
| 7 | 新词上限铁律（>30锁定）无强制手段 | 产品内置锁定机制 |
| 8 | 无移动端/离线体验，依赖 Obsidian + Agent 在线 | Web App，localStorage 持久化，手机浏览器可用 |

## 7. 参照系：同级作品集项目「英语开口练」

同目录下已上线的姊妹项目提供了成熟的工程与文档模式：

- **技术路线**：单文件 HTML + 浏览器原生 API（speechSynthesis TTS / SpeechRecognition / MediaRecorder）+ localStorage，零构建零月费。
- **部署**：GitHub Pages（静态）+ Cloudflare Workers（卡密 API）+ .xyz 域名，免备案。
- **文档流水线**：MVP功能规划 → 商业化评估 → 成本估算 → 灰度验证（量化 Go/No-Go 闸门）→ 反馈收集表 → 方案评审 → 部署手册 DEPLOY.md。
- **决策纪律**：所有文档带日期与状态；"不做什么"边界表与"做什么"同等重要。

**结论**：本环境无 gh CLI / wrangler 云端凭证，上线策略采用「本地部署立即可体验 + 云端一键部署包（DEPLOY.md）」双轨。

## 8. 调研结论：新系统定位

**产品名**：词汇生长（Vocabulary Growth）
**一句话定位**：把 Hermes 验证过的「词汇生长系统 v3」从笔记+对话，变成一个可自助使用的 Web 应用——不背单词，让单词长出来。

**核心闭环（继承自原系统）**：
```
学（词群语块卡）→ 复（分层抢救+遗忘深度）→ 用（造句+老外版本对照+今天用掉）
```

**四不原则（继承方法论立场）**：不做选择题为主的识别训练；不做写作训练；不做"先输入后开口"的路径；不追求大而全课程。
