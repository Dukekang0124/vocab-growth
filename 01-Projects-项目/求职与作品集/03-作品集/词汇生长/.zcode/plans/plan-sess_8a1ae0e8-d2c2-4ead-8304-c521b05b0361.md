# 词汇生长 MVP 版本设计方案

## 一、MVP 功能范围和优先级排序

### 1.1 核心功能（MVP 必须包含）

**P0 - 必须上线功能（100% 完成）**：
- ✅ 今日看板（统计 + 复习入口 + 生长曲线）
- ✅ 学新词（8 词群词卡 + 自定义词）
- ✅ 复习（分层六层提示 + 30秒硬想 + SRS调度）
- ✅ 造句工坊（中译英 + 老外版本对照）
- ✅ 说法库（13 场景语块 + 自测 + 跟读）
- ✅ 我的词汇（主动词库 + 薄弱词 + 数据管理）
- ✅ 移动端适配（375px 响应式 + 离线可用）
- ✅ 本地持久化（localStorage + 导出/导入 JSON）

**P1 - 建议上线功能（1-2周开发）**：
- 🟡 使用次数限制（每日10次复习/5次造句/3个新词/30分钟学习）
- 🟡 微信白名单配置（0.5小时，允许微信内访问）
- 🟡 用户反馈入口（页面底部评分/评论/建议提交）

**P2 - 延后功能（商业化版本）**：
- ⏸️ 云端数据同步（需要用户登录模块，成本较高）
- ⏸️ 付费墙（需要支付集成，商业化后再做）
- ⏸️ PWA 支持（离线缓存，技术复杂度中等）
- ⏸️ 微信分享卡片（需要微信 JS-SDK）

### 1.2 功能优先级矩阵

| 功能 | 价值 | 成本 | 优先级 | 理由 |
|:--|:--|:--|:--|:--|
| 核心功能（P0） | ⭐⭐⭐⭐⭐ | ⭐ | **P0** | 已完成，直接上线验证 |
| 使用次数限制 | ⭐⭐⭐⭐ | ⭐⭐ | **P1** | 防止滥用，收集付费需求，成本低 |
| 微信白名单 | ⭐⭐⭐⭐ | ⭐ | **P1** | 微信是核心传播渠道，0.5小时完成 |
| 用户反馈 | ⭐⭐⭐ | ⭐ | **P1** | 迭代优化必需，1小时完成 |
| 云端同步 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | **P2** | 价值高但成本高，商业化后再做 |
| 付费墙 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | **P2** | 需要支付集成，商业化后再做 |

## 二、技术架构建议

### 2.1 当前架构（已验证）

**前端架构**：
- 零框架纯静态（HTML5 + CSS3 + Vanilla JS ES6+）
- 模块分离：data.js（种子数据）+ srs.js（SRS-lite算法）+ store.js（状态管理）+ app.js（UI渲染）
- localStorage 数据持久化（key: `vocab_growth_v1`）
- Hash 路由 SPA 导航
- 响应式设计（375px 移动优先）
- TTS 发音（OB mp3 优先 + 浏览器 TTS 兜底）

**部署方案**：
- GitHub Pages（推荐）：免费、自动 HTTPS、全球 CDN
- Cloudflare Pages（备选）：免费、全球 CDN、免费 SSL

**测试覆盖**：
- 35 单元测试（数据完整性、算法、状态管理）
- 18 GUI 测试（6 个模块完整流程）

### 2.2 MVP 增强架构

**新增模块**：

1. **usage-limit.js**（使用限制模块）
   - 数据结构：`usage_records: { userId: { date: { reviewCount, sentenceCount, newWordCount, studyTime } } }`
   - 本地存储：localStorage key: `vocab_growth_usage_v1`
   - 限制逻辑：每日次数/时长统计与阈值比对
   - UI 展示：首页顶部使用次数提示 + 达到上限弹窗

2. **feedback.js**（反馈模块）
   - 数据结构：`feedback: [ { id, type, content, rating, email, timestamp, userId } ]`
   - 本地存储：localStorage key: `vocab_growth_feedback_v1`
   - 提交方式：表单（类型：bug/suggestion/feature，评分1-5星，可选邮箱）
   - 展示方式：页面底部固定悬浮按钮 + 反馈弹窗

3. **wechat-whitelist.js**（微信白名单模块）
   - 验证逻辑：检查当前域名是否在微信白名单中
   - 错误处理：微信拦截时提示用户"请在浏览器中打开"
   - 配置文件：`wechat_whitelist.txt`（域名列表）

**数据流设计**：

```
用户操作 → checkUsageLimit() → 返回限制状态
         → recordUsage() → 记录使用次数到 localStorage
         → renderUsageBanner() → 显示剩余次数
         → 达到上限 → showLimitReachedModal() → 付费转化
```

## 三、用户反馈和数据收集方案

### 3.2 数据收集机制

**收集内容**：
1. **使用行为数据**：
   - 每日复习次数、造句次数、新词添加次数、学习时长
   - 复习完成率、薄弱词攻克情况
   - 造句提交次数、造句质量（通过/未通过）
   - 学习曲线（每日学习时长、词汇增长）

2. **功能使用数据**：
   - 各模块使用频率（学新词/复习/造句/说法库/我的词汇）
   - 自定义词添加次数
   - 导出/导入备份次数
   - 使用次数达到上限的次数

3. **反馈数据**：
   - 反馈类型分布（bug/suggestion/feature）
   - 评分分布（1-5星）
   - 反馈内容关键词分析
   - 反馈提交频率

4. **设备与浏览器数据**：
   - User Agent（操作系统、浏览器版本）
   - 屏幕分辨率（响应式适配验证）
   - 是否使用微信内置浏览器
   - 是否使用移动端浏览器

**数据存储**：
- 本地存储：`vocab_growth_feedback_v1`（反馈记录）
- 导出功能：我的词汇 → 数据管理 → ⬇️ 导出反馈数据 JSON
- 导入功能：数据管理 → ⬆️ 导入反馈数据 JSON（仅用于分析，不影响应用）

**数据分析目标**：
1. **功能使用率**：哪个模块使用频率最高？哪个模块使用率低？
2. **用户痛点**：通过反馈内容和评分识别常见问题
3. **付费意愿**：达到使用次数上限的用户付费转化率
4. **留存因素**：哪些功能影响用户留存？
5. **设备分布**：移动端 vs 电脑端使用比例

### 3.3 定期用户访谈与问卷

**用户访谈**（1次/月，5-10人）：
- **方式**：电话/视频/在线问卷
- **问题**：
  1. 您如何了解这个产品的？
  2. 哪个功能最喜欢？为什么？
  3. 哪个功能最难用？为什么？
  4. 您是否愿意付费？为什么？
  5. 您会推荐给朋友吗？为什么？
  6. 您希望产品增加什么功能？

**用户问卷**（1次/季度）：
- **方式**：邮件/在线问卷平台（问卷星/腾讯问卷）
- **内容**：
  - 产品满意度（1-10分）
  - 功能使用频率
  - 付费意愿（付费方案A/B测试）
  - 竞品对比（是否使用其他产品？）
  - 推荐意愿（NPS评分）

### 4.2 推荐方案：双轨分发策略

#### **主渠道：Web链接（GitHub Pages）**

**推荐理由**：
1. **零成本**：GitHub Pages 完全免费，无维护成本
2. **快速上线**：5分钟部署，立即可用
3. **跨平台兼容**：电脑/手机/平板/微信浏览器全支持
4. **易于分享**：复制链接即可分享到任何平台
5. **移动端友好**：375px 响应式设计，手机体验良好
6. **零维护**：无需服务器、无需数据库、无需更新审核

**部署步骤**：
1. 创建 GitHub 仓库（5分钟）
2. 上传代码（2分钟）
3. 启用 GitHub Pages（1分钟）
4. 配置微信白名单（0.5小时，可选）

**推广渠道**：
- 个人社交圈（微信/朋友圈/微信群）
- 知识分享平台（知乎/小红书/B站）
- 技术社区（GitHub/掘金/SegmentFault）
- 英语学习社区（小花生/扇贝/百词斩用户）

#### **备选渠道：微信小程序（商业化版本）**

**推荐理由**：
1. **微信内传播**：微信是核心传播渠道，小程序无需跳转
2. **无需白名单**：小程序天然支持微信内访问
3. **传播速度快**：朋友圈/群聊分享，1秒触达

**适用场景**：
- 当免费版积累1000+用户后
- 当需要推送通知功能时
- 当需要实现更复杂的社交功能时

**开发成本**：
- 开发时间：1-2周（使用 uni-app / Taro）
- 认证费用：¥300/年（微信认证）
- 维护成本：¥500-2,000/年

## 五、上线后关键指标定义（KPI）

### 5.1 核心指标（必监控）

**用户指标**：
1. **DAU（日活跃用户数）**
   - 目标：上线1周内 DAU > 50，上线1个月内 DAU > 200
   - 监控方式：localStorage 记录每日活跃用户（去重）

2. **MAU（月活跃用户数）**
   - 目标：上线1个月内 MAU > 1000
   - 监控方式：月度活跃用户去重统计

3. **留存率**
   - D7留存率（7日留存）：目标 > 30%
   - D30留存率（30日留存）：目标 > 20%
   - D90留存率（90日留存）：目标 > 10%
   - 监控方式：首次访问时间 vs 当前访问时间

4. **用户增长速度**
   - 新增用户数（每日/每周）
   - 用户来源分布（社交圈/知乎/小红书/技术社区）

**使用行为指标**：
1. **学习频率**
   - 每日学习次数：目标 > 3次/日
   - 每周学习天数：目标 > 5天/周

2. **学习时长**
   - 每日平均学习时长：目标 > 15分钟/日
   - 每周平均学习时长：目标 > 75分钟/周

3. **功能使用率**
   - 复习模块使用率：目标 > 80%
   - 造句模块使用率：目标 > 60%
   - 说法库使用率：目标 > 50%
   - 数据管理使用率：目标 > 30%

4. **自定义内容使用**
   - 自定义词添加次数：目标 > 10次/用户
   - 自定义语块添加次数：目标 > 5次/用户

**付费转化指标**（商业化版本）：
1. **付费转化率**
   - 使用次数达到上限后付费转化率：目标 > 5%
   - 查看付费方案后付费转化率：目标 > 3%

2. **付费用户数**
   - 月付费用户数：目标 > 50人
   - 年付费用户数：目标 > 500人

3. **用户生命周期价值（LTV）**
   - 月度付费用户平均贡献：目标 > ¥20
   - 年度付费用户平均贡献：目标 > ¥240

### 5.2 反馈指标（必收集）

**反馈数据指标**：
1. **反馈率**
   - 反馈提交率：目标 > 5%（500个免费用户中至少25人反馈）

2. **反馈类型分布**
   - Bug反馈比例：目标 < 20%
   - 功能建议比例：目标 > 50%
   - 新功能需求比例：目标 > 30%

3. **评分分布**
   - 5星评分比例：目标 > 60%
   - 4星评分比例：目标 > 25%
   - 3星及以下评分比例：目标 < 15%

4. **反馈内容关键词**
   - 常见问题关键词（如"发音"、"卡顿"、"界面"）
   - 常见功能需求关键词（如"云端同步"、"统计报表"）

### 5.3 技术指标（必监控）

1. **页面加载速度**
   - 首屏加载时间：目标 < 1秒
   - 完整页面加载时间：目标 < 2秒

2. **兼容性**
   - 微信浏览器兼容率：目标 > 95%
   - 移动端浏览器兼容率：目标 > 98%
   - 电脑端浏览器兼容率：目标 > 95%

3. **稳定性**
   - 页面错误率：目标 < 1%
   - 数据丢失率：目标 0%

### 5.4 指标监控工具

**免费工具**：
1. **Google Analytics**（需配置GA tracking）
2. **自研监控系统**（localStorage + 定期导出分析）
3. **浏览器控制台日志**（开发调试）

**付费工具**（商业化版本）：
1. **Mixpanel / Amplitude**（用户行为分析）
2. **Sentry**（错误监控）
3. **New Relic**（性能监控）

## 八、风险与应对

### 8.1 技术风险

**风险1：微信白名单配置失败**
- 应对：准备备用方案（直接分享链接到微信，提示用户在浏览器打开）

**风险2：使用次数限制逻辑错误**
- 应对：编写单元测试，覆盖所有边界情况

**风险3：反馈数据存储损坏**
- 应对：定期导出备份，实现数据恢复功能

### 8.2 运营风险

**风险1：用户增长缓慢**
- 应对：多渠道推广（朋友圈/知乎/小红书），优化推广文案

**风险2：用户反馈不足**
- 应对：主动邀请用户反馈（首次使用后弹窗提示），提供小奖励（如7天会员）

**风险3：用户留存率低**
- 应对：优化学习体验，增加学习激励（如学习打卡、成就徽章）

### 8.3 商业化风险

**风险1：付费转化率低**
- 应对：优化付费方案设计，提供更多折扣，优化付费引导时机

**风险2：用户流失率高**
- 应对：增加用户粘性功能（如学习提醒、社交分享），优化用户体验
