# 开发过程归档规范（5 阶段沉淀法）

> 适用：全部开发任务（前端/脚本/部署/调优）。由九思于 2026-08-28 建立，替代"改完就丢、下次重摸索"。
> 原则：每个阶段完成即沉淀，知识可沉淀、可追溯、可复用。

## 阶段与对应文件夹

| 阶段 | 文件夹 | 沉淀内容 | 完成判定 |
|---|---|---|---|
| 01 需求调研 | `01-需求调研/` | 原始反馈/截图/用户原话/来源链接、问题范围界定 | 说清"用户要什么、从哪来的" |
| 02 需求分析 | `02-需求分析/` | 现象描述、根因定位、方案对比与取舍、验收标准 | 说清"为什么坏、选哪条路、怎么算修好" |
| 03 设计开发 | `03-设计开发/` | 改动文件/函数/前后代码 diff、设计理由、语法校验结果 | 说清"改了哪、怎么改、编译过" |
| 04 测试验证 | `04-测试验证/` | 静态校验、标记校验、部署前检查清单、真机/人工待办 | 说清"验了什么、还差什么没验" |
| 05 验收上线 | `05-验收上线/` | 部署报告、线上地址、上线内容、已知限制、回滚方案 | 说清"上线了没、有啥坑、怎么回退" |

## 使用铁律
1. **阶段不可跳**：即使小改动也要走完 5 阶段（小改动文档可短，但不能不写）。
2. **改动即沉淀**：每次改完代码，当天把设计开发/测试验证文档归入对应文件夹。
3. **溯源可查**：文档里写清关联文件、commit、来源，避免"只写结论找不到出处"。
4. **经验资产化**：跨任务可复用的套路（如本项目"纯前端单文件+Cloudflare Pages 免备案部署"）提炼为 SKILL 或记入 MEMORY.md。
5. **部署类任务**：同步源→github 副本→commit→push→验证 五步必须留痕；push 受阻要写明阻塞原因与待执行命令。
