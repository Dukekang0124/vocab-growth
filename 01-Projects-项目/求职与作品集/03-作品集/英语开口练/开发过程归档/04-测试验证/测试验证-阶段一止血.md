## 二、F2 听读打卡（核心修复）

```
=== 环境探测（模拟 iOS 微信）===
canRecord(能录音): false   canScore(能评分): false

=== 听读打卡流程 ===
听完前    : 完成今日打卡（听读 0/4） | 可点 = false
听完 4 句 : 完成今日打卡            | 可点 = true
打卡后    : checkedDays = ["2026-08-29"]   streak = 1
按钮变为  : 今日已毕，明日再来 | 可点 = false
```

**结论**：无录音环境下，听完当日全部句子即可打卡，`streak` 从恒为 0 变为 1。

对照修复前：打卡按钮 `display:none`，且只在 `mediaRecorder.onstop` 里才显形 → 微信用户永远看不到按钮。

## 三、P0-2 打分算法

### 新旧对比（真实代码跑测）

| 场景 | 旧分 | 新分 | 变化 | 说明 |
|---|---|---|---|---|
| 正常念对 | 100 | 100 | 0 | 无误伤 |
| **倒着念** | **100** | **37** | **-63** | 核心 bug 修复 |
| 重复刷分（念 10 遍同一词） | 60 | 45 | -15 | 流利度从 100 降到 73 |
| 念对 + 废话 | 100 | 96 | -4 | 简洁分轻微惩罚 |
| 念对但极慢（0.6 词/秒） | 100 | 91 | -9 | 语速分生效 |
| 漏一个词 | 83 | 88 | +5 | 旧算法重复惩罚漏词，新算法分离衡量 |
| 只念首尾（6 词念 2 词） | 33 | 48 | +15 | 同上，准确度权重已提到 0.7 抑制 |

### 算法说明

- `accuracy` = LCS(`lcsLength`) / 目标词数 —— 词序敏感
- `fluency` = 语速分（1.5–3.5 词/秒正常区间）× 0.7 + 简洁分（LCS/说出词数）× 0.3
- 综合 = `accuracy × 0.7 + fluency × 0.3`

**权重调整记录**：初版用 0.6/0.4，测出"只念首尾"从 33 涨到 53（严重漏词却接近及格），
判断为流利度权重过高，改为 0.7/0.3 后降到 48，准确度主导。
