## 一、改动前
```js
audio.oncanplaythrough = () => {
  audio.playbackRate = Math.max(0.5, Math.min(1.5, rate));
  const p = audio.play();
  if (p && p.catch) p.catch(() => finish(false));   // ❌ 播放被拦立即判失败
};
audio.onplaying = () => finish(true);               // ❌ 一开始播放就推进下一段 → 并发
audio.onerror = () => finish(false);
audio.onabort = () => finish(false);
audio.onended = () => {};                           // ❌ 播完什么都不做
setTimeout(() => finish(false), 4000);
```

## 二、改动后
```js
audio.oncanplaythrough = () => {
  audio.playbackRate = Math.max(0.5, Math.min(1.5, rate));
  const p = audio.play();
  if (p && p.catch) p.catch(() => { /* 拦截不立即失败，交 onerror/超时 */ });
};
// 关键修复：必须等本段真正播放结束(onended)才推进下一段，纠正并发顺序错乱
audio.onended = () => finish(true);
audio.onerror = () => finish(false);
audio.onabort = () => finish(false);
audio.onplaying = () => { /* 仅开始，不推进序列 */ };
setTimeout(() => finish(false), 6000);               // 6s：避免正常短句被 4s 误杀
```

## 三、设计理由
1. **`onended` 才推进**：保证整段播完再播下一段，彻底消除并发，顺序天然正确。
2. **`onplaying` 空操作**：仅作"已开始"信号，不再触发 `finish`。
3. **`play()` catch 不立即失败**：微信里偶发策略拦截时，留给 `onerror`/超时判定，避免误杀正常播放。
4. **超时 4s→6s**：TTS 段通常 1–4s，放宽到 6s 防止正常长句被误判失败触发不必要的源切换。
