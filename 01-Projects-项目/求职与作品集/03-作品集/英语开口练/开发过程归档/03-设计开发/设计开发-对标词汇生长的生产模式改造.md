### 三个底层原理

1. **记忆靠挣扎不靠重复**——提取时越挣扎记得越牢（desirable difficulty）
2. **语言是语块不是单词**——老外说话是整块蹦的，教「I'm curious about...」不教「curious=好奇的」
3. **遗忘是数据不是失败**——卡在哪层 = 记忆强度信号，驱动复习安排

### 三环结构

```
学（语块优先）→ 复（分层抢救+遗忘深度）→ 用（纠正+老外版本）
```

### 分层抢救 v2（七层，一次只给一层）

```
0 硬想30秒 → 1 词性 → 2 词义 → 3 首字母 → 4 长度 → 5 半句场景 → 6 答案
铁律：每层之间等用户回答；给答案后必重造句 + 标深度
```

### 遗忘深度

| 档位 | 层数 | 复习节奏 |
|---|---|---|
| 🟢 记得牢 | 0-1 | 隔天复习 |
| 🟡 有点生 | 2-3 | 当天 + 隔天 |
| 🔴 要攻克 | 4+ | 重点清单 + 词根拆解 + 造3句 |

### 其他关键设计

- **纠正四分类**：语法(grammar) / 搭配(collocation) / 用词(word choice) / 地道(naturalness)
- **必给「老外会说」版本**——不是只改错，是给原汁原味说法
- **新词上限铁律**：待复习 > 30 → 锁定新词添加，防僵尸词积累
- **4R 激活循环**：Retrieve（限时提取）→ Rephrase（改写升级）→ Reuse（场景复用）→ Record（录音记录）

## 二、差距分析：最致命的是模式错位

| 环节 | 词汇生长 | 英语开口练改造前 |
|---|---|---|
| 输入方式 | 给中文/场景 → 自己产出英文 | 给英文 → 照着念 |
| 想不起来 | 七层渐进提示逼你想 | 直接显示答案 |
| 反馈 | 四分类纠正 + 老外会说版本 | 一个分数 + 词级 Diff |
| 复习 | 遗忘深度驱动排期 | 无复习，30 天循环 |
| 推进 | 待复习 >30 锁定新词 | 学完就走，僵尸词积累 |

**根因**：产品所有环节都是**识别模式**（对话=选择题、词卡=看词看释义、跟读=照着念），
而开口需要**生产模式**。这正是康哥自己在 OB 方法论第 1 条写的：
> 「App 训练的是识别模式，开口需要的是生产模式——两套能力不互通」

## 三、改造实现

### G1 中→英盲说模式（生产模式）

**交互流程**：
```
句子卡片显示英文+中文，下方盲说区显示中文
  ↓ 点「我想试试」
英文变 ■■■ 遮罩 + 播放/慢速/录音按钮禁用（防止偷看偷听）
  ↓ 用户看中文自己说
点「我想起来了」→ 记录 rescue=当前层数，揭示英文
点「想不起来」  → 记录 rescue=6，揭示英文
```

**关键代码**：
- `blindBoxHtml(key, sceneIdx, sentIdx, s)` 渲染盲说区
- `blindSlot(key)` 管理运行时状态（不落盘）
- 遮罩实现：`s.en.replace(/[A-Za-z0-9]/g, '■')`
- 遮罩时 `lockPlay = ' disabled style="opacity:.35;pointer-events:none;"'`

**最大价值**：**不依赖录音和语音识别**，微信等降级环境可完整使用。
这是唯一在所有环境都能跑通的核心练习——比录音打分覆盖面更广。

### G2 分层抢救七层提示

`hintForSentence(en, zh, level)` **由句子自动计算生成，无需维护额外内容**：

| 层 | 内容 | 生成方式 |
|---|---|---|
| 1 | 词性 | 问句/陈述句 + 总词数（检测 `?` 结尾） |
| 2 | 词义 | 直接取中文 `zh` |
| 3 | 首字母 | 第一个词 |
| 4 | 长度 | 每个词的字符数序列 |
| 5 | 半句场景 | 前一半词 |
| 6 | 完整答案 | 全句 |

一次只给一层，逐层累积显示（`.blind-hints` 容器）。

### G3 遗忘深度 + 复习队列

**数据结构**：
```js
state.sentenceStats['sceneIdx-sentIdx'] = {
  last,        // 上次练习日期
  rescue,      // 用到第几层提示（0-6）
  depth,       // green / yellow / red
  due,         // 下次复习日期
  times,       // 练习次数
  greenStreak  // 连续🟢次数（移出薄弱用）
}
```

**排期规则**（对标词汇生长）：

| rescue | depth | due |
|---|---|---|
| 0-1 | green 记得牢 | +1 天 |
| 2-3 | yellow 有点生 | 今天 |
| 4-6 | red 要攻克 | 今天 |

**复习区设计**：
- `DEPTH_RANK = { red: 0, yellow: 1, green: 2 }` 弱项优先排序
- **只回收往日场景**的句子（今日场景已在主区，避免重复渲染）
- red 句边框高亮 + 顶部提示「有 N 句上次是看答案过的，今天重点攻克」
- 当日区 yellow/red 显示「今天就再练一次」

## 四、踩坑记录

1. **替换 state 字段时留下残留行**：用 `Edit` 替换多行时，原内容末尾的 `};` 与后续行会残留，导致语法结构错乱。改后必须 grep 确认 `};` 只有一处。
2. **`filter(d => x || true)` 让过滤永远失效**：初版复习区写了 `d.sceneIdx !== currentIdx || true`，导致当日句子重复出现在复习区。
3. **盲说 key 必须用复合键**：初版用数字 `i` 作 key，复习区与当日区索引冲突导致状态串台。改为 `d{idx}` / `r{scene}-{sent}`。
4. **yellow 的 due 曾排成明天**：词汇生长规定 🟡 是「当天 + 隔天」，即当天要再练一次。初版 `calcDue` 对 yellow 返回 `addDays(1)`，已修正为 `addDays(0)`。

## 六、复用价值

这套设计（生产模式 + 分层抢救 + 遗忘深度）**不限于英语产品**，可迁移到任何「从输入到输出」的学习场景：
背单词、背法条、背产品知识、技能练习。

核心公式：
```
遮住答案 → 逼自己产出 → 分层给提示 → 记录卡在第几层 → 按层数排复习
```
