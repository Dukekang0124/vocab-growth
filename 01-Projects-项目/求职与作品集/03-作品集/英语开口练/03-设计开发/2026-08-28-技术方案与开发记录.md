## 二、关键问题与解决方案

### 2.1 微信内置浏览器TTS不可用 ⭐ 核心问题

**问题**：微信内置浏览器使用X5内核，不支持 `window.speechSynthesis`，点击播放提示"浏览器不支持语音功能"。

**尝试过的方案**：
1. ❌ Web Speech API — 微信X5内核不支持
2. ⚠️ edge-tts预生成MP3 — 可行但生成749个文件耗时长、部署体积大
3. ✅ **有道TTS在线服务** — 最终采用

**解决方案**：
```javascript
// 有道TTS URL格式
const url = 'https://dict.youdao.com/dictvoice?audio='
  + encodeURIComponent(text) + '&type=2';  // type=2 美式女声

const audio = new Audio(url);
audio.play();  // 微信支持<audio>播放
```

**降级策略**：
```
有道TTS播放 → 失败 → Web Speech API → 失败 → Toast提示
```

**慢速实现**：`audio.playbackRate = 0.7`（无需生成两个版本）

**经验总结**：
- 国内Web App的TTS方案，优先考虑国内服务（有道/百度），不要假设Web Speech API可用
- 在线TTS URL比预生成音频文件更灵活，适合内容频繁更新的场景
- edge-tts适合需要离线或固定内容的场景，但700+文件的生成和部署成本高

### 2.2 微信录音每次都要授权

**问题**：微信内置浏览器每次调用 `mediaRecorder.start()` 都会弹出麦克风授权提示。

**结论**：这是微信的安全策略，**无法通过代码绕过**。

**应对**：
- UI上明确提示"点击录音"，让用户有预期
- 授权后在同一页面会话内不需要重复授权（但关闭页面后需重新授权）
- 录音按钮设计得足够明显，减少用户困惑

### 2.3 微信不支持语音识别（自动评分）

**问题**：`webkitSpeechRecognition` 在微信中不可用，自动评分功能失效。

**解决方案**：降级为"录音+自行对照"模式
```javascript
if (!SR) {
  onResult({ unsupported: true });
  // UI显示："当前浏览器不支持自动评分，录音已保存，可对照标准发音自行校正"
}
```

**后续升级方向**：接入讯飞/百度语音评测API（需后端+付费）

### 2.4 个人主体无法接入微信支付

**问题**：微信支付JSAPI需要企业营业执照，个人收款码在微信浏览器内无法长按识别。

**尝试过的方案**：
1. ❌ 微信支付JSAPI — 个人不可用
2. ❌ 收款码长按识别 — 微信安全限制，不识别付款码
3. ❌ 收款码点击放大 — 放大后仍无法识别
4. ❌ 微信内打开支付链接 — 无法唤起微信付款
5. ✅ **内测期免费** — 先验证产品价值
6. 📋 **正式期方案**：面包多/柠檬赞等第三方平台（个人可用，5%手续费）

**经验总结**：
- 个人开发者做微信内支付，不要走微信支付直连，直接用第三方聚合平台
- 内测阶段最重要的是验证需求，不是收费，免费反而降低体验门槛

### 2.5 部署平台选择

**踩坑过程**：

| 平台 | 问题 | 耗时 |
|------|------|------|
| GitHub Pages | 国内DNS污染，微信可能被拦截 | - |
| Netlify | 注册需hCaptcha人机验证，国内加载失败 | 30分钟 |
| 腾讯EdgeOne Pages | 需个人认证，认证流程复杂 | 20分钟 |
| Cloudflare Pages | ✅ 免费、国内可访问、GitHub自动部署 | 15分钟 |

**Cloudflare Pages部署流程**：
1. 注册Cloudflare账号
2. Pages → Connect to Git → 选择GitHub仓库
3. 授权Cloudflare访问GitHub仓库
4. 构建设置：Framework preset=None，Build output=/
5. 保存部署，获得 `xxx.pages.dev` 域名
6. 后续git push自动触发部署

**Cloudflare Pages直传bug**：
- 直接拖拽上传文件夹时，中文路径的文件可能变成空文件名
- 解决方案：通过GitHub仓库连接部署，不使用直传

**GitHub连接问题**：
- 安装Cloudflare GitHub App时，Repository access选择"Only select repositories"
- 选择目标仓库后，如果下拉列表不显示，刷新页面
- 回调URL可能跳转错误，手动导航到Pages创建页即可

### 2.6 单文件架构的优缺点

**优点**：
- 零构建、零依赖、部署简单
- 一个文件就是整个应用，便于分享和备份
- 没有跨域问题（同域）
- 适合作品集展示

**缺点**：
- 文件较大（600KB+，含base64图片）
- 代码维护性随功能增加而下降
- 不适合多人协作

**适用场景判断**：功能模块<10个、无复杂状态管理、无需后端逻辑时，单文件是最佳选择。

## 五、后续开发指引

### 添加新内容
- 新场景：在 `DAILY_SCENES` 数组添加
- 新单词：在 `WORDS` 数组添加
- 新对话：在 `DIALOGS` 数组添加
- 新跟读：在 `REPEAT_SENTENCES` 数组添加
- TTS自动支持新内容，无需额外操作

### 新增功能模块
1. 在 `<body>` 中添加新的 `.view` 容器
2. 在底部导航添加Tab按钮
3. 在 `<script>` 中添加render函数
4. 在 `switchView()` 中注册路由
5. 遵循降级兼容原则

### 切换到正式付费版
1. 将 `BETA_MODE` 改为 `false`
2. 部署Cloudflare Workers（见 `cloudflare-workers/DEPLOY.md`）
3. 设置 `API_BASE` 为Worker地址
4. 配置面包多等支付平台
5. 更新反馈弹窗为付费弹窗
