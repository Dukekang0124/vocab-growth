# 会话归档（上下文释放）流程

## 何时用
- 用户说"上下文快满了/沉淀会话/释放上下文/梳理归纳会话"
- 长会话收尾，信息量大，需要完整落盘

## 核心原则：先查后做，不重复造轮子
接任务第 0 步先查 OB 已有沉淀（`01-记忆库`、`02-知识库/03-运维与恢复`、`04-SKILL`、今日日志），
**会话主线已沉淀过的内容不重写**，只补缺口（新增信息、决策、坑、待办）。

## 标准流程（5 步）

### 第 1 步：盘点已有沉淀（只读）
```bash
# OB 结构 + 01-记忆库 + 相关分类目录 + 今日日志是否存在
ls "/d/写作工具/知识管理/08-九思搭档知识库/01-记忆库/"
ls "C:/Users/Admin/WorkBuddy/2026-08-21-09-30-00/.workbuddy/memory/2026-08-24.md"  # 今日日志
grep -n "^#\|^##" "<已有相关文档>"  # 看已有文档覆盖度
```

### 第 2 步：识别缺口（关键！）
对照会话主线，找出**尚未沉淀**的信息，通常是：
- 新增决策（如"408 处残留=历史事实不改"）
- 新踩的坑 / 新经验
- 待办遗留
- 时间线（跨多天的会话）

### 第 3 步：写归档文档
- 位置：`01-记忆库/YYYY-MM-DD-主题-会话归档.md`
- 结构：时间线 → 问题与解决方案（表格）→ 关键决策 → 经验固化清单 → 核心坑 → 待办 → 收尾四查
- **补缺口优先**：已有文档缺的信息，追加进已有文档（如"残留分类决策"章节）

### 第 4 步：固化 skill（若产生新可复用流程）
本归档流程本身 = 可复用 → 固化为 `04-SKILL/session-archive/SKILL.md`（即本文档）。
其他新经验按「经验资产化铁律」评估是否固化为新 skill。

### 第 5 步：沉淀日志 + 汇报
- 写今日日志 `memory/YYYY-MM-DD.md`（append-only）
- 更新 `02-知识库/00-索引.md`（如有新文档）
- 给用户交付清单：哪些已沉淀、哪些新补、哪些已固化、可放心释放上下文

## 注意
- **历史快照/日志/审计不改**：modify_backup、file-history、logs、audit-log 是历史事实
- 归档是"落盘"，不是"删内容"——信息完整不丢失
- 上下文释放后，后续检索靠 OB 归档文档 + 记忆文件，不靠会话记录
