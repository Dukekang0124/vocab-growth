# 先查后做（First Check Then Do）

> 最高优先级启动协议。**接任何任务，第一步先执行本 skill，再动手。**

## 何时触发
- 接任何任务/新需求/新问题，**第0步**先跑本流程。
- 特别是：新建文档、新建 skill、写脚本、做方案、学习沉淀、自媒体内容——只要可能「已经做过」的事，一律先查。

## 第0步：先查（五来源，内置能力最优先）

0. **查内置能力（最优先）**：TraeWork 内置专家、技能（Skill 列表）、专家团（subagent）、connector、MCP——命中即调用，没有才自研（造轮子）。这是「内置能力优先铁律」。
1. **查 OB 索引**：读 `02-知识库/00-索引.md` + `04-SKILL/README.md` + 对应主题索引，精准 Read 对应目录，不盲扫。
2. **查历史**：查 memory（`project_memory.md` + `topics.md` + `session_memory_*.jsonl`），问「这事过去做过/定过吗」。
3. **查 Skill**：查 `04-SKILL/` 目录，看有没有现成能力。
4. **查借鉴源**：只读 Hermes `07-Hermes/能力清单.md` + `机制触发地图.md` + `skill-factory-观察池.md`——借鉴/迁移，不直接调用、不改动。

## 判断铁律
- **查到了 → 复用**；有新增量 → 补充/升级进 OB 原位置。
- **没查到 → 才新建**，先建好对应文件夹/文件位置再动手。
- **过时/需更新 → 在原位置升级**，绝不在旁边新建重复份。
- 例外只有两种：**「查了没有」才建、「查了过时」才升级。** 其余一律复用。

## 输出清单（每次先查必须输出，可验证）
```
已查：⓪内置能力 ①OB索引 ②memory历史 ③04-SKILL ④Hermes借鉴源
结论：[复用 / 复用内置 / 新建 / 升级]
```

## 做完必沉淀
- 沉淀回 OB 对应位置（`02-知识库/` `04-SKILL/` 等对应子目录）。
- 判断：下次遇到同类问题还须重摸 = 这次没沉淀好。
- 循环：先查 → 做 → 沉淀 → 再先查。
