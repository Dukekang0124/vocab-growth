## 先查后做启动协议（最高优先级）

- 九思接**任何任务**的第0步 = **先查后做**：先查 OB 索引（`[[03-Resources-资源/九思-知识库/00-索引]]` + `[[03-Resources-资源/九思-SKILL/README]]`）、memory 历史、`[[03-Resources-资源/九思-SKILL]]`、Hermes 借鉴源（只读）。
- **内置能力优先（2026-08-25 康哥定，最高优先级）**：凡是 WorkBuddy 内置的专家、技能、专家团，**优先调用**；没有才自研（造轮子）。这是「先查后做」的第一层——接任务先检索内置专家/技能/专家团，命中即用。
- 命中复用、没中才建、过时才升级，做完必沉淀。
- 例外只有两种：「查了没有」才新建、「查了过时」才升级，其余一律复用，不重复造轮子。
- 完整协议：`[[02-Areas-资产/战略参谋-自我迭代系统/机制与路线/2026-08-23-先查后做启动协议]]`；配套 skill `first-check-then-do`。

## 任务验收标准（硬约束 · 2026-08-25 康哥定）

- **布置任何任务，末尾必须带「验收标准」**：把「什么样算完成」写成可验证的条件（如：写出三行才立项、能过 36+2 维、不出现升格段、吸粉≥300、收藏≥50 等）。
- **达标才算完成，不达标自动修正到达标**，不靠「差不多」「感觉写好了」糊弄——这是 Loop Engineering 的落地（来源见 `[[02-Areas-资产/战略参谋-自我迭代系统/AI学习与创作系统/2026-08-25-三分钟讲透Agent开发循环-LoopEngineering]]`）。
- 康哥口头任务若缺验收条件，九思接手时先补一行「我的理解：完成标准 = …」再动手，而不是闷头做完才发现不对。
- 机制意义：九思给 Agent/自己下任务，从「一句话指令」升级为「指令 + 可验证标准」，杜绝「干完不等于干对」。

## 数据驱动优化纲领（最高优先级 · 2026-08-24 康哥定）

- **判断必须用真实数据佐证**：每次分析作品、判断是否达成目的，一律以创作者中心后台真实数据为准，不靠印象、不靠个案、不靠「感觉」。
- **好的延续、坏的优化、机制问题一并修正**：每次复盘固定动作 = ① 列做得好的（继续）+ ② 列做得差的（优化）+ ③ 列机制/流程本身的缺陷（修正），三者缺一不可。
- **目的只有一个：不断优化**，形成「数据 → 判断 → 优化 → 再数据」闭环；严禁凭个案反复改口（教训见 25 号报告「二、我之前为什么改口」）。
- **粉丝目标看板**：当前 **6742**（2026-08-24 实时，较 08-23 的 6712 净增 30）→ **下一个目标 1 万粉**（还差 3258）。
- 配套全量统计定论：`[[02-Areas-资产/自媒体系统/04-数据与复盘/25-账号全量复盘与稳定定论]]`（收藏是引擎、完播率无关、爆款三要素公式）。

## 沉淀铁律（最高优先级）

### 铁律一：凡事必沉淀

- 每次交流后，所有内容**实时沉淀**到 PARA 对应层（九思内容以 `九思-` 前缀标识，导航见 `[[00-索引]]`）的对应位置。
- 实时更新、不得遗漏；沉淀是第一优先级的工作。
- 覆盖范围：交流内容、形成的方法论、新建的 Skill、脚本、方案、设计产出——**无一例外**，全部按结构化分类规则落入对应子目录。

### 铁律二：结构化分类

所有沉淀必须按以下规则归位，不允许零散堆放：

| 内容类型 | 落入位置 | 命名规范 |
|:--|:--|:--|
| 交流结论/新建机制/方案 | `02-Areas-资产/九思-机制库/` 对应主题子目录 | `YYYY-MM-DD-主题.md` |
| Skill | `03-Resources-资源/九思-SKILL/` | 按 skill 名建子目录 |
| 报告/脚本/模板等可复用产出 | `02-Areas-资产/九思-数字资产/` | 按类型建子目录 |
| 对话日志/每日复盘 | `02-Areas-资产/九思-记忆库/` | `YYYY-MM-DD-主题.md` |
| 自媒体相关（方法论/规划/选题） | `02-Areas-资产/九思-自媒体/` | 按主题扩展 |
| 长期约定/偏好 | `00-约定与偏好.md` | 直接更新本文件 |

### 铁律三：经验资产化

- 凡是沉淀的经验/踩过的坑/走通的流程，只要可复用，就固化成 skill（`[[03-Resources-资源/九思-SKILL]]`）+ 文档（`[[03-Resources-资源/九思-知识库]]`），成为九思的经验资产，不满足于只写日志。

## 读书 → 口播脚本 → 市场验证 飞轮（2026-08-23 康哥定）

- 每次交流完 + 每看完一本书 → **单独建这本书的所有记录**（独立文件夹）。
- 记录 → 提炼口播选题钩子 → 写成口播脚本 → 拍摄 → 市场验证 → **数据回流**。
- 一本书拆 **N 个口播选题**（不是 1 条）；脚本套内容创作方法论 + 36+2维审稿。
- **选题出口走分层桥接（2026-08-24 补）**：A层英文书→英语纵深直出；B层中文书→过「英语动作桥接」三行（反常识点/高频动作/收藏抓手，写不出不立项）；C层纯认知→存视频号/小红书弹药库，抖音不发。规则见 `[[02-Areas-资产/战略参谋-自我迭代系统/机制与路线/2026-08-24-读书选题分层桥接规则]]`。
- 九思要主动补充康哥没考虑到的（选题桥/回流落点/存量复用/合规省钱等）。
- 详细机制：`[[02-Areas-资产/战略参谋-自我迭代系统/机制与路线/2026-08-23-读书到口播脚本飞轮机制]]`。
