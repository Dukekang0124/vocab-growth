## 一、标准开发流程（5步）

### 第1步：需求拆解 + 数据源探查

**做什么：**
- 把康哥的需求拆成具体功能点
- **先探查数据源是否存在、格式是什么、能不能自动获取**
- 不要假设能拿到数据，先验证

**关键动作：**
```bash
# 探查本地数据目录
Get-ChildItem "目标路径" -Recurse -Depth 2
# 检查文件格式（LevelDB/SQLite/JSON/CSV）
# 尝试解析二进制文件，搜索关键词
```

**经验：**
- 豆包客户端数据在 `%LOCALAPPDATA%\DoubaoWork\User Data\Default\IndexedDB\`，是Chromium LevelDB二进制格式，**没有公开解析接口**
- 遇到不可自动获取的数据源，**立刻换方案**，不要死磕逆向解析
- 半自动方案（AI自动记录+手动补记）往往比全自动逆向更稳定

### 第2步：方案设计 + 铁律对齐

**做什么：**
- 根据数据源情况确定架构（全自动/半自动/手动）
- 对齐6条铁律：
  1. 全量沉淀OB
  2. 全窗口覆盖
  3. 先查后做，不重复造轮子
  4. 经验资产化（方法论/工作流/skill）
  5. 免费模型优先
  6. 内置能力优先（先查Skill清单）
- 确定文件存放位置（D盘OB对应目录）

**输出：** 一句话方案说明 + 文件清单

### 第3步：开发（数据→脚本→看板）

**标准文件结构（每个工具一个文件夹）：**
```
工具名/
├── README.md          # 使用说明（必写）
├── xxx_data.json      # 数据文件
├── xxx_tracker.py     # 核心脚本（记录+生成+检查）
├── xxx看板.html        # 完整版HTML看板（Chart.js，带筛选器）
└── xxx.md             # OB原生Markdown报告（Mermaid图表+表格）
```

**开发顺序：**
1. 先写数据结构（JSON schema）
2. 再写核心脚本（log命令 + report命令 + check命令）
3. 最后生成HTML和Markdown

**脚本标准命令：**
```bash
python xxx.py log --model "模型" --category "环节" --task "描述" --cost high/low/free
python xxx.py report    # 生成HTML+MD
python xxx.py check     # 检查阈值/预警
```

### 第4步：测试 + 真实数据验证

**做什么：**
- 用今天的真实数据录入测试
- 验证预警机制是否触发
- 验证HTML看板能否正常打开
- 验证Markdown在OB里Mermaid图表是否渲染
- 验证文件路径是否都在D盘OB

**关键检查：**
- 预警阈值是否合理
- 图表数据是否正确
- 中文是否乱码（UTF-8）
- 临时文件是否清理

### 第5步：沉淀OB + 更新长期记忆

**做什么：**
- 所有文件写入OB对应目录
- 写README使用说明
- 在长期记忆文件中加入"自动记录/自动调用"规则
- 把开发经验提炼成本方法论文档
- 清理C盘临时文件

## 二、关键经验与坑

### 经验1：HTML看板 + Markdown报告双输出

- **HTML看板**：功能完整（筛选器、交互图表），用Chart.js CDN，浏览器打开
- **Markdown报告**：OB原生查看，Mermaid图表+表格，文件更新OB自动刷新
- 两者同时生成，满足不同场景

### 经验2：数据内嵌 vs 外部加载

- HTML看板用数据内嵌（`<script>const D = {...}</script>`），避免file://协议CORS问题
- Markdown报告每次重新生成，数据直接写在md里
- 不要用fetch加载本地JSON，浏览器会拦截

### 经验3：预警机制要在记录时即时触发

- `log`命令执行后立即检查阈值，有预警直接打印
- 不要等用户主动check才发现超限
- 预警分两级：达到80%（接近）、达到100%（已达上限）

### 经验4：LevelDB/SQLite不要硬解析

- 客户端内部数据格式是二进制序列化，逆向成本高、不稳定、更新就失效
- 优先用"AI侧自动记录"方案——我在执行任务时自己记账，比解析客户端日志可靠10倍

### 经验5：深色主题看板

- HTML看板统一用深色主题（#0f1117背景，#1a1d28卡片）
- 图表颜色用明亮色系（蓝/绿/黄/红/紫）
- 表格hover高亮，badge区分算力类型

## 三、四查清单（开发交付前）

- [ ] **查全**：需求的所有功能点都实现了吗？
- [ ] **查准**：数据统计正确吗？阈值预警触发正常吗？
- [ ] **查沉淀**：所有文件都在D盘OB吗？README写了吗？长期记忆更新了吗？
- [ ] **查风格**：看板美观吗？中文不乱码吗？结论明确吗？
