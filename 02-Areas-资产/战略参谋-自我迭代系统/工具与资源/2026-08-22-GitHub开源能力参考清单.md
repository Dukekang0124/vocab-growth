# GitHub 开源能力参考清单（主动找方案弹药库）

> 2026-08-22 · 联网调研 GitHub/MCP 生态后沉淀，供「主动找解决方案」机制调用
> 核心结论：WorkBuddy 原生能力已覆盖大半，不盲目装 MCP，按需取用

---

## 一、MCP 生态真相（先泼冷水）

- 公共注册表 **2 万+ MCP server**，但约 **2/3 有安全问题**（被放弃的周末项目/半成品实验）。
- 权威建议：**别装 50 个，选 3-5 个匹配真实需求的**——超过 5-7 个，Agent 会被工具膨胀拖慢、变笨。
- 三条铁律：①锁版本 ②Token 只读直到观察过 ③永远别让 Agent 对生产环境循环写。

## 二、官方推荐的核心 MCP（按需参考）

| MCP | 用途 | 康哥要不要 |
|:--|:--|:--|
| **GitHub** | 操作仓库/PR/Issue/代码搜索 | ✅ 连接（找开源能力）|
| Context7 | 拉取最新文档，防 API 幻觉 | 🟡 看情况 |
| Playwright | 浏览器自动化 | ❌ 已有 agent-browser |
| Filesystem | 受控文件访问 | ❌ 已有原生文件工具 |
| Brave Search | 网络搜索 | ❌ 已有 WebSearch |

## 三、关键判断（九思超越 Hermes 的底座）

康哥要的"查官网/GitHub + 找能力"，**WorkBuddy 原生已有一大半**：

| 需求 | WorkBuddy 原生 | 还要不要装 |
|:--|:--|:--|
| 联网查官网/GitHub | WebSearch/WebFetch ✅ | 不用 |
| 浏览器操作/截图 | agent-browser skill ✅ | 不用 |
| 操作 GitHub | GitHub connector（待连接）| 连上即可 |
| 文生图/视频 | ImageGen/VideoGen ✅ | 不用 |
| 领域专家 | 100+ 专家 ✅ | 不用 |
| 外部服务 | 100+ connector ✅ | 按需连接 |

**结论**：九思缺的不是"装更多 MCP"，而是 **①激活 GitHub 连接 + ②让"主动找"自动化**。这两点已通过「主动找方案三层机制」落地。

## 四、后续按需候选（真遇到具体需求再装）

- 需要拉最新技术文档 → Context7（免费）
- 需要抓特定网页数据 → 评估专用爬取类 MCP
- 需要接某个 SaaS（飞书/钉钉/网盘等）→ 直接用内置 connector
