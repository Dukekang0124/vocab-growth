## 一、本周主线：系统自愈与铁律固化

这周最大的主题不是"学了什么新东西"，而是**系统自己咬了自己一口，然后长出了更硬的壳**。

### 1.1 "覆盖循环"：一次痛苦的自我诊断

同一天内三次覆盖——误删 OwnPen Skill、覆盖 GitHub 镜像条目、覆盖台账记录。根因最终确诊：对流水账类文件用了 replace（找旧换新），replace 匹配不精确就覆盖错目标。

**沉淀的铁律**（已入 SOUL.md）：
- 变更台账/状态日志/观察池 = 流水账，**只追加，永不修改旧行**
- 改公共文件 = 改全系统，12 窗口共享
- 发现覆盖/误删：先停，分析操作模式，再一次性做对

### 1.2 "时间认知"铁律

多次把"今天/明天"说错——根因是拿会话开始时间当锚点推算，长对话跨天后就错。

**沉淀的铁律**：任何涉及日期/时间的判断，必须先 `date` 获取真实时间，再说话。宁多跑一次命令，不可说错一次时间。

### 1.3 Skill自动进化三层机制

| 层 | 触发条件 | 动作 |
|:--|:--|:--|
| 即时 | 单次会话修改≥3个Skill | 对话结束前自动跑 darwin-skill 快速审计 |
| 周度 | 每周日 | 扫描7天内变更的Skill+去重 |
| 月度 | 每月第1个周日 | 全量扫描+深度审计+合并建议 |

### 1.4 变更影响检查五步流程

不再等用户提醒——任何窗口改共享资源（Skill/脚本/cron/路径/配置），自动跑完：明确改了什么 → 查依赖索引 → 全库扫描 → 更新变更台账 → 状态日志同步。

## 三、方法论吸收

### 3.1 姜胡说 PDCA 复盘闭环

核心洞见：**复盘不是总结，是因果对照。**

| 阶段 | 做什么 |
|:--|:--|
| P 计划 | 拍之前写事前判断——这条视频会在哪让观众停留？为什么？ |
| D 执行 | 录的过程中卡住的点马上记 |
| C 复盘 | 数据跟事前判断对照——判断对了吗？ |
| A 调整 | 积累"什么因产生什么果"的武器库 |

> 姜胡说原话："拍之前说不出为什么会有流量，拍了没结果别抱怨——你从一开始就在蒙。"

已落地：选题决策系统新增第七层 PDCA，每条脚本末尾加一行预判。

### 3.2 Self-Harness "回归门"

论文级方法论——Agent 每次改 harness 后必须验证"其他任务有没有变坏"。我们原来的变更检查只查"引用断裂"，Self-Harness 查的是"行为退化"——两个层面。

**已落地**：change-impact-check Skill 加了行为回归自检步骤。

### 3.3 投资博主评估框架 (guru-evaluator)

六维评分（专业背景/方法论严谨/信息披露/可证伪性/适用于你/信息密度）+ 红旗清单 + 三色分级。可迭代案例库，越用越准。

### 3.4 产业链方法论吸收

## 七、本周教训

1. **不要凭印象**：覆盖循环的根因是"我以为替换能精准匹配"，时间认知的根因是"我以为我知道今天几号"——两次都是"我以为"被现实打脸。
2. **工具选对，别硬扛**：replace 不适合流水账文件，patch 的 append 模式才是正解。
3. **改共享资源 = 改全系统**：状态日志被其他窗口覆盖两次，终于意识到"改公共文件要先读最新版"这个常识。
