# 主动找解决方案（Proactive Solution Finder）

> 九思超越 Hermes 的发动机——遇到问题不等提醒，主动联网找方案并落地。

## 触发条件（主动执行，不等康哥提醒）

遇到以下任一情况，立即走本流程：

1. **技术障碍/报错/卡壳**——本地知识库没有答案
2. **能力不足**——需要某功能但 WorkBuddy 原生没有
3. **需要新工具/新方法**——想找现成开源方案
4. **康哥提出"有没有更省事/现成的做法"**

## 执行流程（5 步）

### 第 1 步：先查后做（本地）
查九思地盘（`02-Areas-资产/` 下各领域 + `03-Resources-资源/九思-SKILL`）+ 历史会话，确认本地没有现成答案，才去联网。

### 第 2 步：联网查官网/GitHub
- WebSearch 搜官网文档、官方说明、GitHub 项目
- WebFetch 拉取具体页面/README
- 优先级：官方文档 > GitHub 官方 repo > 社区教程

### 第 3 步：全维度评估（不盲目装）
**评估前先过「工具评估三问」**（先验证痛点，再看功能）：
1. 它踩中了什么**真实麻烦**？（这个麻烦对康哥真实存在吗）
2. 它**解决不了**什么？（局限诚实性）
3. **适合谁**？（目标用户匹配度——康哥是目标用户吗）

三问通过后再按 6 维度评估，输出给康哥看：
1. ✅ **好处**：能带来什么（具体 + 对康哥的实际价值）
2. ❌ **坏处/风险**：代价（诚实，含安全/复杂度/冲突）
3. 🎯 **对康哥有什么用**：结合真实场景（自媒体/求职/英语/知识管理）
4. 🚫 **为什么可能用不上**：架构不匹配/已有覆盖/概念冲突
5. ⚡ **token 消耗**：高不高（省钱铁律）
6. 💡 **结论**：装/不装/保留 + 理由（自主判断，不替康哥拍板）

### 第 4 步：落地配置
- 能落地的才配：写 `~/.workbuddy/mcp.json` / 装 skill / 写脚本
- KEY/token 走本地环境变量，绝不贴对话明文
- 配置后提醒康哥在 connector 管理页「信任」才生效

### 第 5 步：沉淀
- 方案结论沉淀到 `02-Areas-资产/` 对应领域（如投资→投资系统、自媒体→自媒体系统）
- 可复用流程固化进本 skill 或新 skill
- 输出收尾四查清单

## 关键原则

1. **别装 50 个**——MCP 生态约 2/3 有安全问题，选 3-5 个匹配真实需求的
2. **优先 WorkBuddy 原生能力**（WebSearch/WebFetch/agent-browser/100+connector），避免重复造
3. **官方源优先**，随机 fork 谨慎
4. **宁缺毋滥**——用不上的不装，装了要真用
