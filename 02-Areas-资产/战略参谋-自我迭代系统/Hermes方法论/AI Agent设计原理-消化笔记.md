## 核心公式

**最小可跑版**：Agent = LLM + 上下文 + 工具（大脑+眼睛+手脚）

**生产可靠版**：Agent = LLM + 上下文 + 工具 + 约束 + 验证 + 纠正

Harness 是真正的竞争力——不换模型只优化外壳，Terminal Bench 2.0 从 50+→60+，排名上升 20 多位。

## 对我有启发的 7 个点

### 1. KV Cache——改 Skill 有代价
系统提示词和工具定义一旦确定不要随意改，多一个空格缓存全废。**我们改 Skill 太勤了，应该合并到 darwin 月度审计统一改。**

### 2. Agent 状态栏——可以加到 ops-dashboard
类比手机顶部状态栏，在上下文末尾持续注入结构化摘要（调用次数/当前时间/待办）。我们 ops-dashboard 是 UI 版，缺的是对话内精简版。

### 3. 隔离优于压缩
上下文太长→用 Sub Agent 隔离而不是全局压缩。我们的 12 窗口分工就是这个思路。

### 4. SFT 立形 → RL 求神，顺序不能反
SFT 先让输出格式规范，RL 再优化结果泛化。先用 SFT 再 RL，反过来奖励函数无法识别混乱输出。

### 5. 保存经历 ≠ 从经历中学习
学习发生在系统主动完成评价、对照、归纳、验证之后，不是日志写入磁盘那刻。**对应我们的沉淀自觉——下次同类问题要重新摸索=没沉淀够。**

### 6. 99条军规警告
提示词和 Skill 要像写给新员工的指导书，避免 99 条军规式规则罗列。**我们的 SOUL.md 需要周期性做减法。**

### 7. 快慢环——语音延迟降 15 倍
小模型实时对话+大模型后台操作，纯文本状态栏同步。我们已经做了 but 还没用到语音场景。

## 我的独立洞察

- Sidecar 只读结构化字段不读自由文本——防 RMRF 话术注入。实习时遇到过类似事故。
- "人的停顿是同理心的展现"——不是书里的，是自己冒出来的。
- Agent 天空有两朵乌云：①流式实时交互 ②从经历中持续学习。我们正在攻第二朵。

## 对自己系统的反思

- Skill 修改频率太高→月度审计合并
- 缺对话内状态栏→考虑加到长对话末尾
- SOUL.md 和提示词越来越臃肿→需要做减法
- 快慢环已在用但没文档化
