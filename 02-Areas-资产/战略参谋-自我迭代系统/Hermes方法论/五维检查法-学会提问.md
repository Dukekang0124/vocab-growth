# 🧠 五维检查法（《学会提问》→九思思考工具）

> 2026-08-12 消化沉淀。来源：公众号文章《我把<学会提问>做成了Prompt，改掉GPT爱附和的坏毛病》。
> 价值：把"独立思考铁律"系统化成可操作的检查框架。

## 核心认知：前提错误
```
你以为问题在A，拼命在A上用力——但没检查问题是不是真在A。
例子：方案被拒→改PPT（问题是方向不是表达）/进步慢→多学（问题是输出不是输入）
AI时代更危险：带倾向提问，AI顺着你+找理由支持错误逻辑（听起来有道理≠真的有道理）
```

## 五维检查法（判断/决策/审稿通用）

| 维度 | 问什么 | 例子 |
|:--|:--|:--|
| **① 前提检查** | 判断背后藏什么假设？假设验证过吗？| "方案被拒→改PPT"藏着"问题是表达"（没验证）|
| **② 逻辑检查** | 前提→结论中间跳步了吗？| "竞品上功能→我们也上"（跳了"用户相同吗"）|
| **③ 证据检查** | 支撑的是数据/经验/感觉？区分了吗？| "我觉得市场大"=感觉，"行业报告40%"=数据 |
| **④ 替代解释** | 认定的原因是唯一解释吗？| 试用期差=能力不行？（也可能是培训/管理/职责问题）|
| **⑤ 遗漏检查** | 有什么关键信息我不知道？反对者会说什么？| "如果结果很差，最可能因为什么？"|

## 必须修原则（最重要）
```
⚠️ 光指出问题不帮解决 = 抬杠（挖坑不埋）
✅ 每次指出问题后，必须给方案：
   前提有问题→重新定义问题
   逻辑跳步→补上缺的台阶
   证据不够→说清需要什么证据
```

## 落地到九思OS
```
✅ socratic-interview（苏格拉底追问）→ 加五维框架
✅ 审稿（oral-script-review #25逻辑一致性）→ 已有4步自检，可对齐五维
✅ 独立思考铁律 → 五维=实操方法（不只"不同意就说"，而是"五维检查后说"）
✅ 用户提问/决策辅助 → 先五维检查再回答（不附和）
```

## 触发
- 用户做重要判断/决策时 → 五维检查
- 用户投喂方案/想法 → 检查前提+逻辑+证据（不顺着说）
- 审稿/分析 → 对齐五维
