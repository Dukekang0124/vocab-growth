# AI 架构的独立性原则

## 核心观点

**客户端、记忆引擎、知识库、模型——四个组件各自独立，通过 Skill 互相调用，不深度绑定任何一个供应商。**

这样一旦某个服务出问题（封号、涨价、被淘汰），换一个就行，其他部分不受影响。

## 苏不倦当前架构（2026-07-18 更新）

| 组件 | 当前方案 | 独立性 | 变化 |
|---|---|---|---|
| 客户端 | Hermes Agent | 🟢 开源，可自部署 | — |
| 主模型 | DeepSeek V4 Pro | 🟢 国内服务，可替换 | — |
| 视觉模型 | 智谱 GLM-4V | 🔴 余额不足，dashscope 不兼容，三个全挂 | ⚠️ 待修复 |
| 记忆/知识库 | Obsidian（本地） | 🟢 完全本地，不受云服务影响 | 路径更新为 PARA 结构 |
| 对话记录 | Hermes session DB | 🟡 本地 SQLite，可导出 | — |
| 微信接入 | Hermes Gateway + iLink Bot | 🟡 依赖微信平台 | delivery 格式已修正为 weixin |
| Skill 系统 | Hermes Skill（5个自建） | 🟢 本地 .md 文件，纯文本可迁移 | 🆕 +4 个自媒体 Skill |
| 墨问发布 | mocli v0.4.1 | 🟢 本地 CLI，可替换 | 🆕 新增 |
| cronjob | 2 个定时任务 | 🟢 本地调度 | 🆕 新增 |

> 八个组件中六个绿。视觉模型是当前唯一的红灯。

## 泛函的补充

- 用 API 中转站调用不同模型 → 避免单一模型封号风险
- 记忆引擎用 OpenViking（第三方独立存储）→ 不跟客户端绑死
- 所有重要产出同步飞书文档 → 知识资产的第二份保险

## 一句话

> 不被任何一家 AI 产品绑死。每个组件都能换，整个系统就不会塌。
