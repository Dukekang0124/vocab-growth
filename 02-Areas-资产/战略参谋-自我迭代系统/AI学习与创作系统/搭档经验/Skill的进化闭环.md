# Skill 的进化闭环

## 核心方法

泛函的 Skill 迭代闭环：

```
AI 用 Skill 写稿 → 人手动改 → 
AI 对比两个版本，学习为什么改 → 
把 bad case 写进 Skill → 
下次完美符合要求
```

**Skill 不是写完就完了——每次人工修改都是 Skill 的进化数据。**

## 跟苏不倦的关系（2026-07-18 验证）

闭环已跑通。实际进化案例：

| 环节 | 例 |
|---|---|
| AI 审稿提建议 | 给结尾写了修改文案 |
| 你手动改 | 没用 AI 的文案，自己写了更简洁的版本 |
| AI 对比差异 | 发现：你的结尾比 AI 版更简洁有力 |
| 写入 Skill | 规则：「结尾只做诊断，不给具体文案」 |
| 下次更精准 | 之后所有审稿，结尾只指出问题，不代写 |

> 「结尾只诊断不处方」这个规则不是设计出来的——是你一次手动修改喂给 Skill 的。闭环在转。

## 一句话

> 最好的 Skill 不是一次性写出来的，是一次次被你的手动修改喂出来的。

## ⚠️ 反向进化陷阱 🆕

> 无管控的零散优化叠加后，Skill 反而越改越差。实测：初始版 10 轮完成任务 → 迭代 2 周后变成 20 轮。

解法：**Evaluation（评估体系）+ 版本管理（Git 仓库）**。每次改动对比新旧效果，出问题可回滚。
