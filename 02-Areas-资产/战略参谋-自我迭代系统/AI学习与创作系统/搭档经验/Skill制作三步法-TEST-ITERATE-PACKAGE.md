# Skill 制作三步法：TEST → ITERATE → PACKAGE

## 核心流程

不需要代码。三步把个人工作流变成可复用的 Skill：

| 步骤 | 做什么 | 底层逻辑 |
|---|---|---|
| **STEP 1** | 识别真实需求，用通用 Prompt 让 AI 跑通一次全流程 | TEST（测试验证可行性） |
| **STEP 2** | 根据你的审美标准和偏好，持续反馈优化，直到输出完全匹配你的要求 | ITERATE（迭代打磨效果） |
| **STEP 3** | 向 AI 发出指令，把前两步沉淀的迭代规则封装，生成可复用的专属 Skill | PACKAGE（封装沉淀能力） |

## PACKAGE 阶段的两个关键优化（Frontend Slides 实战验证）

| 优化 | 做什么 | 效果 |
|---|---|---|
| **设计引导流程** | 生成前先出 3 版封面预览让用户选风格 | 避免 AI 生成不符合预期的通用化设计，省 token |
| **模板库搭建** | 收集参考图 → 引导 AI 生成 30+ 套预设模板，按主题自动匹配 | 解决「每次生成效果千篇一律」的痛点 |

> 核心理念：**先出成品，后封 Skill。** 不要从 Skill 起步——Skill 是迭代的最终产物，不是初始目标。

## 举例：苏不倦口播审稿 Skill 的三步对应

| 步骤 | 你做的事 |
|---|---|
| TEST | 第一次让 AI 审一篇脚本，看它能不能识别结构问题 |
| ITERATE | 每次 AI 给的建议你手动改，反馈「这个说法我不会用」「那个判断标准不对」 |
| PACKAGE | 把所有反馈规则整理成一个审稿 Skill，下次直接调用 |
