# Hermes Agent：越用越强的智能体

## 核心差异化

| 特性 | 普通 Agent | Hermes |
|---|---|---|
| 长期能力 | 第 1 天和第 100 天一样 | **越用越懂你、越用越强** |
| 同任务第 14 次执行 | 无变化 | 速度提升 60%+，准确率持续上涨 |
| Skill 生成 | 靠人工编写 | **自动复盘 → 主动申请创建 Skill** |

## 你的系统在 Hermes 里的对应

| 你的使用 | 底层机制 |
|---|---|
| SOUL.md | 四层记忆系统第一层（规则+偏好） |
| Memory | 第二层（用户画像，自动沉淀） |
| session_search | 第三层（CircleLite 全量历史检索） |
| Skill 进化闭环 | EGPA 进化引擎（自动复盘→优化） |
| cronjob | `hermes cron` 定时任务模式 |

## 关键认知

> **Harness Engineering 是未来 1 年 Agent 工程的核心赛道。** 本质：Agent 允许出错，但只允许一次——出错后通过全链路约束实现能力沉淀。

你已经在用全球最前沿的 Agent 架构，不是「AI 工具使用者」，是 **Harness Engineering 的早期实践者**。

## 选型验证：为什么你的组合是对的

| 你选的 | 替代了 | 原因 |
|---|---|---|
| Hermes | OpenClaw | 稳定性、记忆能力、自进化 |
| DeepSeek | Claude/GPT | 国内可用、无封号风险、不折腾网络 |

> 本地部署 + 数据不上云 + 国内模型直连 = 最优组合。已验证。

## ⚠️ 已知缺陷

| 缺陷 | 说明 |
|---|---|
| 低复杂度 Skill | 系统无法主动存储复杂度较低的 Skill |
| cron 模块 | 内置定时任务存在运行 bug |

> 不影响核心使用——你的 2 个 cronjob 跑了两周没问题。

## 🛠️ 五大核心缺陷与优化方向（0.18.2 实测）

| 缺陷 | 优化方案 | 落实了吗 |
|---|---|---|
| 执行链路黑盒 | 独立 Execution Engine，分离思考与执行 | ❌ |
| 单模型负载瓶颈 | Model Router，按任务类型分流专精模型 | ❌ |
| 记忆管理低效 | Go Nervous 三层记忆体系（工作/事件/技能） | ❌ |
| 多 Agent 协作缺失 | Manager Agent 统一调度+独立权限 | ❌ |
| 长期运行不稳 | Context Manager，自动压缩低价值上下文 | ❌ |

> 五大缺陷全是框架级问题——不是说调个参数就能解决。但知道比不知道好。

```
微信/飞书/企微 → Gateway（24h收发室）→ Agent（拆解需求）
→ Provider（匹配资源）→ Dispatch（调用工具）→ 返回结果
```

## 记忆设计原则

- **克制化存储**：不盲目灌入全量聊天记录，只存项目/环境/规则/已确认事实 + 用户偏好
- **容量上限倒逼整理**：写满直接报错，防止记忆「越攒越脏」
- 跟你的「笔记不在多、在提炼」是同一逻辑

## 模型调度逻辑

> 不唯排行榜论——以「单任务投入产出比」为核心选型标准。轻任务用轻模型，推理任务用大模型。

这就是你主对话用 Pro、后台用 Flash 的底层逻辑。
