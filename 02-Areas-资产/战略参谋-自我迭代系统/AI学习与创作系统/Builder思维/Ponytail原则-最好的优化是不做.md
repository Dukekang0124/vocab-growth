# Ponytail原则：最好的东西是你没做的东西

> ✅ 已验证：GitHub `DietrichGebert/ponytail`，86.6K Star，MIT协议，v4.8.4。注意：用户内容标注6.8K，实际86.6K。

## 核心洞察

Ponytail是一个给AI编程Agent用的Skill——让它在写代码之前先走一套「决策阶梯」：这东西真的需要存在吗？→ 标准库能做吗？→ 原生特性？→ 已有依赖？→ 能一行搞定？

**你不写代码。但这条原则是你整个系统最需要的思维方式。** 你的11窗口、10个cron、28个Skill正在膨胀。最好的优化不是加新东西，是定期问「这个还需要吗？」

## Ponytail决策阶梯（通用版）

任何「我要做一个新东西」之前，走这五级：

| 级别 | 问自己 | 
|:--|:--|
| ① 真的需要吗？ | 不做会怎样？选题库里有没有能合并的？ |
| ② 现有能力覆盖吗？ | 已有Skill/Cron能做吗？Obsidian自带功能？ |
| ③ 能不能简化？ | 这个流程能砍到一步吗？能用一个窗口解决三个窗口的事吗？ |
| ④ 有没有现成的？ | 哪篇老笔记写过？哪个Skill已经包含这个逻辑？ |
| ⑤ 最少做多少？ | 不是「完整方案」，是「最小可跑版本」——剩下的以后再说 |

## 跟苏不倦的关系

你的系统正在快速膨胀。这条原则应该在总长审计时作为核心检查项：
- 遍历所有Skill → 哪些超过1个月没用过？
- 遍历所有cron → 哪些产出你已经不看？
- 新建之前 → 先走五级决策阶梯

**「你没写的代码永远不会出bug。你没建的Skill永远不会腐化。」**
