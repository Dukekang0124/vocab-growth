> 定位：**帮康哥消化为主**——九思主导执行拆书流水线，康哥在关键节点确认，产出可复用的方法论 + skills + 运用清单

## 一、灵魂（继承 Hermes「运用优先」）

- **读书的终点是用，不是藏。**
- **藏灰检查**：读完一周内没有「用」的动作 = 这次阅读失败。
- 流程：当前缺什么 → 最有用的书 → 最有价值的章节 → 深度内化 → 运用。

## 二、消化流水线（融合 cangjie RIA-TV++ + Hermes 方法论产出）

| 阶段 | 动作 | 产出 |
|:--|:--|:--|
| 0 | 选书：问康哥缺什么 → 从书架/书单挑 | 书单确认 |
| 1 | 素材：本地 PDF/EPUB 优先；微信读书划线降级 | 纯文本 |
| 2 | 整书理解（Adler 四步：结构/解释/批判/应用） | BOOK_OVERVIEW.md → **先给康哥确认骨架** |
| 3 | 并行提取（5 提取器：框架/原则/案例/反例/术语） | candidates/ |
| 4 | 三重验证（跨域佐证 / 预测力 / 独特性，通过率 25-50%） | verified.md |
| 5 | RIA++ 构造（R原文/I重写/A1案例/A2触发/E执行/B边界） | 原子 skills |

## 三、每本书的产出物

- **BOOK_OVERVIEW.md**：整书骨架（主旨/结构/术语/批判）
- **核心方法论笔记**（Hermes 格式）：作者 + Skill 名 + 核心模型表 + 速查表 + 可操作清单
- **DIGEST.md**：精华长文（不读全书、只看精华）
- **skills 工具包**（cangjie 输出，可安装到 ~/.workbuddy/skills/）
- **运用清单**：这本书的方法下次在哪用（藏灰检查依据）

## 六、超越 Hermes 的点

- Hermes：手工提炼「核心方法论」笔记（无质量门槛）。
- 九思：cangjie RIA++ 流水线——**三重验证 + 压力测试 + 可调用 skill + Zettelkasten 链接**，产出是"可执行工具"不是"笔记"。
- 模型策略：深度拆书用 Pro（保质量）；自动化/轻量用 Flash（省钱）。

## 七、可进化机制（2026-08-22 康哥确认：不是固定死的）

- 本机制**可进化升级**：每次消化后复盘，持续优化，不死板。
- 进化方式：
  1. 消化后反馈：哪些提取器/阶段效果好/差 → 写回本机制。
  2. 新工具试跑：book-to-skill 等备选工具跑通后纳入工具栈。
  3. skill 生命周期：使用≥3次固化，长期闲置淘汰。
  4. 康哥反馈优先：消化产出应用后，康哥的使用反馈驱动机制迭代。
- 对齐 Hermes「闭环可进化」并升级：机制本身也被监控迭代，防止过拟合。
