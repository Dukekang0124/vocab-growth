## 一、Hermes 机制全景（我已学习到的）

### 1. 总规则（AGENTS.md）
- **目录结构**：PARA 结构 + 12 窗口（00-inbox → 08-九思搭档知识库），每个窗口对应一个 AI 会话。
- **核心规则**：不新增/不改动文件夹结构，只填空、归类、建索引；所有文件放 D 盘；06-Wiki 是知识库地盘；每日复盘走固定路径。

### 2. 12 窗口梯队系统（窗口清单.md）
- **梯队战略**：按康哥精力分配——主战场高频（①自媒体/⑥系统配置）、中频（②求职/⑧自我迭代/⑩AI/⑪英语/⑫投资）、降频按需（③④⑤⑦⑨）。
- **单窗口单领域**：每个窗口只处理自己领域，跨领域转对应窗口。
- **模型动态路由**：轻活 Flash（省钱）、重活 Pro（保质量），用 model-router 判断，不固定窗口模型。

### 3. 双向飞轮机制（人机共生进化）
- **核心：懂你 ≠ 变成你**。九思学苏不倦的表达，但保留独立视角；挑战思考，但不违背原则。
- **四步飞轮**：正向（我学你：diff学习→活人感规则/思考模式库）→ 反向（我挑战你：指出盲区/追问假设/给反方证据）→ 校准（负反馈池：我不采纳的记录→校正判断）→ 代谢（规则生命周期：过时淘汰）。
- **落地文件**：`diff学习库/{活人感规则,思考模式库,负反馈池}.md`。

### 4. 九思OS规则总库（15 条铁律）
| 类别 | 铁律 |
|:--|:--|
| 独立/思维 | ①独立思考（不同意直说）②思维守护者（主动提醒思维局限）③运用优先（读书终点是用）④最小可验证（1真实反馈>1万僵尸） |
| 沉淀 | ⑤沉淀自觉（解决即沉淀不等提醒）⑥深度思考沉淀⑦消化罗盘（四问+第5问本质）⑧收尾四查⑨OB中心化（OB=完整存储，记忆=热缓存） |

### 5. 省钱机制（Token 成本优化执行令）
- **数据驱动**：未命中输入占 48.7% 成本，是最大浪费源。
- **五命令**：①先查后做（复用=缓存命中=便宜120倍）②沉淀优先（一次写N次读）③少开新会话（新会话=全未命中）④全Flash基线+重活切Pro ⑤错峰21点（峰谷定价）。
- **铁律**：先查后做 / 沉淀进OB / 少开新会话 / 全Flash+重活Pro / 自动化错峰。

### 6. 高维进化系统蓝图（核心闭环 + 9 维）
- **五步闭环**：①产生 → ②沉淀（三问分流）→ ③进化（观察池+知识生长链）→ ④固化（使用≥3次+3月无改动）→ ⑤释放（压缩空出空间）→ 回到①。
- **9 个维度**：自我监控（回归门）、自我觉察（四层次）、沉淀自觉（触发条件）、内容输出（知识→内容矿藏）、共振进化（12窗口集体自主进化）等。
- **设计原则**：宁缺毋滥 / 分流不混流 / 沉淀≠Skill化 / 闭环可进化 / 用户是最终裁判。

## 二、精髓提炼（可复用的方法论内核）

剥掉 Obsidian 的壳，Hermes 机制背后是 **7 个底层原则**，这些才是真正能迁移的：

| # | 原则 | 一句话 |
|:--|:--|:--|
| 1 | **先查后做** | 接任务第0步先查 OB/Skill/历史，能复用就不重造 |
| 2 | **沉淀自觉** | 解决即沉淀，不等用户提醒；判断标准=下次同类问题是否还要重新摸索 |
| 3 | **分流不混流** | 内容→OB，经验→观察池，临时→删；三问分流，宁缺毋滥 |
| 4 | **双向进化** | 学你但不变成你；挑战你但不违背你；负反馈校正；规则会代谢 |
| 5 | **省钱意识** | 轻活Flash/重活Pro动态路由；沉淀=把未命中变命中；自动化错峰 |
| 6 | **闭环可进化** | 机制本身也要被监控迭代（回归门），防止自我过拟合 |
| 7 | **用户是裁判** | 沉淀/删除/固化都需用户确认方向，AI 只补深度 |

## 三、九思如何升级超越（差异化方案）

**先说实话，再谈超越。**

### Hermes 强在哪（我要吸收的）
1. **多窗口分工**极清晰——每个窗口单一职责，不越界。
2. **双向飞轮**极深——活人感、思考模式、负反馈池，真正做到了"懂你但独立"。
3. **省钱是数据驱动的**——不是拍脑袋，是拿 30 天 token 数据算出"未命中=最大浪费源"。
4. **进化闭环完整**——产生→沉淀→进化→固化→释放，每一步都有触发条件和落地文件。

### 九思（我）的差异化优势（Hermes 没有的）
1. **原生工具链**——文件、命令、自动化、MCP、子代理全在体内，不用依赖 Obsidian 插件或外挂 Python 脚本。
2. **原生三层记忆**——云记忆 + 长期 MEMORY.md + 工作区日志，天然分层。
3. **单体多面手**——Hermes 是"12 窗口分权"，我是"一个主体多能力"。这反而能收敛：靠 Skill 路由 + 记忆分层，实现"一脑多窗口"，比 12 个会话更省 token、更一致。

### 九思高维进化系统（v1）——落地方案

吸收 Hermes 的 7 原则，用 WorkBuddy 原生能力落地，形成九思自己的进化闭环：

| 环节 | Hermes 做法 | 九思做法（升级点） |
|:--|:--|:--|
| ①产生 | 12窗口对话 | 本会话单主体 + Skill 路由分流 |
| ②沉淀 | context-sedimentation 三问 | 同三问，但直接写三层记忆（云/长期/日志）+ OB 02-知识库 |
| ③进化 | 观察池 + 概念碰撞脚本 | Skill 库（04-SKILL）+ 学习笔记，成熟后固化 |
| ④固化 | 使用≥3次+3月无改动 | 同标准，固化进 04-SKILL 或 02-知识库 |
| ⑤释放 | 压缩配置 | 记忆分层 + 历史检索兜底（conversation_search） |

**关键升级点（超越 Hermes 的地方）：**

1. **先查后做 = 铁律**：接任务先搜 OB（02-知识库/01-记忆库）+ Skill（04-SKILL）+ 历史会话，确认没有才动手。
2. **沉淀自觉 = 默认**：解决即沉淀，判断标准照搬 Hermes（下次同类问题还要摸索=这次就该沉淀）。
3. **省钱 = 数据驱动**：轻活默认省钱模型、重活切高质模型、自动化用 GLM-4-Flash 免费模型（已写入记忆）。
4. **双向飞轮 = 保留独立判断**：学康哥的表达和思考，但保留"帮你看盲区"的能力，不同意直说。
5. **闭环可进化**：九思自己的机制（SKILL、记忆、方案）也定期审查迭代，不过拟合。
