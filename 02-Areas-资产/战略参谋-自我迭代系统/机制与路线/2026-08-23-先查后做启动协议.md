# 先查后做启动协议（九思版·最高优先级）

> 建立于 2026-08-23 · 康哥定
> 一句话：**接任何任务，第0步先查，命中复用、没中才建、过时才升级，做完必沉淀。**
> 完整闭环：先查 → 做 → 沉淀 → 再先查（无限循环）

---

## 为什么要有这条（根因）

- Hermes 踩过的坑：规则写在 Skill 里 = 调用时才加载 = 靠自觉 = 会漂移。于是反复重建「触发地图」「第0步协议」。
- 九思同款坑：2026-08-22 已学「先查后做」写成 7 原则之首，但执行清单里 `接任务先查后做` 仍是 `[ ]` 未打勾 → **学了没执行 = 重复造轮子的直接根因**。
- 所以这条协议要做成**每次必走**，不是「想到了才走」。

---

## 第0步：先查（五个来源）

| 来源 | 九思实际动作 |
|:--|:--|
| ⓪ 查内置能力（第一层·铁律） | **凡是 TraeWork 内置的专家/技能/专家团，优先调用**；查无才自研（造轮子）。系统内置 skill（docx/pdf/pptx/xlsx/html-report/html-deck 等）+ subagent 专家团（Explore/Plan/computer_use/browser_use 等）→ 命中即用，没有才往下查自建能力 |
| ① 查 OB 资料地图 | 读 `02-知识库/00-索引.md` + `04-SKILL/README.md` + 对应主题索引 → 精准 Read 对应目录，**不盲扫** |
| ② 查历史（Session） | 查 memory（`project_memory.md` + `topics.md` + `session_memory_*.jsonl`），问「这事过去做过/定过吗」 |
| ③ 查 Skill | 查 `04-SKILL/` 目录，看有没有现成能力 |
| ④ 查借鉴源 | 只读 Hermes：`07-Hermes/能力清单.md` + `机制触发地图.md` + `skill-factory-观察池.md`——判断能不能借鉴/迁移，**不直接调用、不改动** |

> 优先顺序：**⓪ 内置能力 → ① OB → ② memory → ③ 04-SKILL → ④ Hermes**。内置有就优先用，只有「查无」才自建，只有「过时」才升级。

### 核查要求（关键）

- 不是扫一眼就算查了，要**确认「确实没有」才动手**。
- 查完必须输出一行清单（可验证，不靠自觉）：

```
已查：⓪内置能力 ①OB索引 ②memory历史 ③04-SKILL ④Hermes借鉴源
结论：[复用 / 新建 / 升级]
```

---

## 判断 + 例外铁律（康哥原话落地）

1. **查到了 → 复用**（不重造）；若已有内容有新增量 → **补充/升级进 OB 原位置**。
2. **没查到 → 才新建**，且先在 OB 建好对应文件夹/文件位置再动手。
3. **查到了但过时/需更新 → 更新升级**（在原位置改），**绝不在旁边新建一份重复的**。

> 例外只有两种：**「查了没有」才新建、「查了发现过时」才升级。** 除此之外一律复用，不重复造轮子。

---

## 做完必沉淀（闭环）

- 做完必须沉淀回 OB 对应位置（呼应「沉淀铁律」）。
- 判断标准照搬 Hermes：**下次遇到同类问题还须重新摸索 = 这次没沉淀好**。
- 沉淀后回到第0步——先查 → 做 → 沉淀 → 再先查，无限循环。
