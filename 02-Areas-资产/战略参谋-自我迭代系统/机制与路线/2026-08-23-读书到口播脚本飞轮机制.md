# 读书 → 口播脚本 → 市场验证 飞轮机制

> 2026-08-23 · 九思 × 康哥 · 把「读书消化」和「自媒体口播」焊成一个闭环飞轮
> 核心规则：每次交流完 + 每看完一本书 → 建这本书的所有记录 → 提炼口播选题 → 写成脚本 → 拍摄 → 市场验证 → 回流

---

## 一、飞轮全景（五步闭环）

```
①读书消化（02-知识库/读书消化）
   → 读书记录 + 9类skill + 提炼「口播选题钩子库」
        ↓
②选题卡（06-自媒体规划/02-选题 或 02-知识库/04-选题库）
   → 每个钩子 = 1 张选题卡（挂到选题系统8分制评估）
        ↓
③口播脚本（06-自媒体规划/口播脚本）
   → 套内容创作方法论 + 36+2维审稿
        ↓
④拍摄发布 → 数据（04-数据与复盘/单作品分析SOP）
        ↓
⑤市场验证回流 → 哪类选题/书爆了 → 读书记录补"验证结果" → 选题库更新 → 下次优先
```

## 二、每本书 = 独立记录文件夹

康哥规则「单独建这本书的所有记录」，落地为：每本书一个文件夹，所有记录归拢：

```
02-知识库/读书消化/<主题>/01-读书笔记/<书名>/
├── BOOK_OVERVIEW.md       ← 整书骨架
├── DIGEST.md              ← 精华长文
├── verified.md            ← 三重验证记录
├── candidates/            ← 候选池（审计）
├── skills/                ← 拆出的 skill 工具包
├── 口播选题钩子库.md       ← 🆕 从书里提炼的可拍钩子（反直觉观点/金句/案例）
└── 市场验证.md             ← 🆕 脚本发出去后的数据反馈回流
```

## 三、读书 → 口播的「选题桥」（关键补充）

**读书记录 ≠ 口播脚本**，中间必须过一道"选题提炼"：
- 一本书拆 **N 个口播选题**，不是 1 条。例：《超越感觉》至少能拆 10+ 条——
  - "你以为是你在想，其实是环境在想你"（第一章·被塑造）
  - "25 种思维谬误，你中了几个"（第二篇·谬误速查）
  - "为什么你总被带节奏"（立场错误·视角匮乏）
  - "你跟人吵架总输，不是嘴笨，是没识别谬误"（fallacy-spotter）
- 每个选题套**钩子公式**：反常识观点 + 痛点 + 反转 + 行动号召（对齐已有内容创作方法论）。

## 四、「市场验证」要回流（关键补充）

康哥规则止于"拍摄放到市场上验证"，我补上回流闭环：
- 脚本发出去 → 数据（播放/点赞/评论/涨粉/完播）→ 走 `04-数据与复盘/18-单作品系统分析SOP`。
- **哪类选题爆了 → 写回这本书的 `市场验证.md` + 更新选题库规律**。
- 作用：知道"哪本书、哪类观点"能打，下次读书/选题优先往这个方向走。
- 例：如果"谬误识别"类口播爆了，说明粉丝要"识别他人谬误"的爽点 → 下本书优先挖同类。

## 五、康哥没明说、我补上的（6 点）

1. **一本书多脚本**：不是"读完写 1 条"，是"读完产一个选题池，按需出脚本"。
2. **交流完 ≠ 读完书**：两条沉淀线都要走——交流完走「铁律一」沉淀结论；读完书走本飞轮。
3. **存量书复用**：书架 3102 本 + 已消化的《超越感觉》，无需重新看也能直接出脚本。
4. **拆出的 skill 本身就是口播素材**：9 个 skill（谬误速查器等）既是工具，也是选题富矿。
5. **合规 + 省钱**：脚本发布前过 `self-media-compliance-review`；选题/脚本用 Flash，深度拆书才用 Pro。
6. **数据回流的落点**：读书记录里要留 `市场验证.md` 空位，别等验证了才发现没地方记。
