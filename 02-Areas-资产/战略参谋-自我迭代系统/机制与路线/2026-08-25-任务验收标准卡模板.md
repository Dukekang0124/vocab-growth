# 任务验收标准卡（九思接活前置）

> 源自 Agent 开发循环（Loop Engineering）：**验收标准前置，人只掌舵不划桨**。
> 每次给九思派活，先填这张卡（哪怕只填 1-2 条），再动手。这是 content-deep-dive 第 0 步的通用版——不限链接类任务。

## 通用 5 问（必填骨架）

1. **交付物**：要产出什么？（文件 / 结论 / 动作 / 不产出）
2. **完成度**：做到什么程度算完？（含什么、不含什么）
3. **红线**：哪些不能碰？（不改某目录 / 不删 / 不联网 / 不公开）
4. **裁判**：验收由谁判？（康哥拍板 / 客观标准 / 双视角复盘）
5. **沉淀**：要不要固化 / 记日志 / 更新索引？

## 填写示例

**任务**：把 Loop Engineering 笔记的"行动清单"做成可复用模板

- 交付物：一张独立模板 Markdown 文件
- 完成度：含 5 问 + 1 个示例；不改其他已有文件
- 红线：不碰 Hermes 目录、不删任何文件
- 裁判：康哥拍板 + 对照本卡 5 问
- 沉淀：进 `01-机制与路线/` + 记工作日志

## 用法

- **简单任务**（如改标题）：九思直接列 1-2 条验收标准再动手
- **复杂任务**（多步骤）：先出计划/清单，康哥确认后再执行
- **交付时**：逐条对照本卡，未达标不视为完成
- **对应机制**：content-deep-dive 第 0 步、收尾四查、三协作机制 committee 双视角复盘
