# 决策记录（ADR）

## ADR-1：撤销"独立性铁律"，改为协同统一管理
- **背景**：原约定"九思绝不改动 Hermes、相互独立存在"。
- **决策**：撤销该铁律，改为"九思与 Hermes 协同统一管理"，允许重组 Hermes 目录以实现统一管理。
- **影响**：Hermes 目录可改动；九思机制/技能库可与 Hermes 体系去重、协同。
- **落实**：枢纽文档 `00-约定与偏好.md` / `README.md` 已校正为"协同统一管理"（无旧铁律残留）。

## ADR-2：vault 重组骨架保持 PARA 四顶层不变
- **决策**：01-Projects / 02-Areas / 03-Resources / 04-Archive 四顶层编号与定位不变；其下子文件夹可自由重组。
- **影响**：九思体系以 `九思-` 前缀落入各 PARA 层；Hermes 以 `07-Hermes` 独立顶层存在。

## ADR-3：空壳复发根因 = app-config.json（治本而非反复删目录）
- **现象**：`08-九思搭档知识库` 空壳删了又生。
- **根因**：`C:\Users\Admin\.workbuddy\app\app-config.json` 第 2 行 `"defaultWorkspacePath"` 仍指向 `08-九思搭档知识库\工作空间`，WorkBuddy 启动自动重建该目录。
- **决策**：改配置 → `D:\写作工具\知识管理\08-九思-工作空间`（与 vault 根真实工作空间一致）；改后重启 WB 验证空壳不再生。automation 的 cwds 三处已正确指向新路径，锅不在 automation。
- **影响**：这是 P0 必修项，不修等于没治本。

## ADR-4：Hermes 应完整并入 07-Hermes
- **决策**：根级游离的 `05-Skills` / `06-Wiki` / `AGENTS.md` 收编进 `07-Hermes`（06-Wiki→`07-Hermes/06-Wiki`；AGENTS.md→`07-Hermes/05-指南交接/`；05-Skills 内容→`07-Hermes/02-技能与工具/` 或 `九思-自媒体`）。
- **影响**：消除"Hermes 半并入"的分裂状态，实现真协同。待执行（P1）。

## ADR-5：事实澄清 — "Hy3" 非代码项目（重要）
- **澄清**：用户提及的"Hy3 项目 / Hy3 代码"经磁盘搜索（workspace 根、D 盘全量）**确认不存在为代码项目**。
- **事实**：vault 中 "Hy3" 仅出现在一篇技术文章素材 —— `2026-08-22-投稿稿-Hy3限免撞墙429踩坑记录.md` 及两张图（`hy3-429-error-*.png`、`hy3-429-cover-*.png`），即腾讯云开发者社区首篇文章主题。
- **决策**：后续若用户再提"Hy3 代码/项目"，**先搜磁盘确认真实路径，不凭空假设、不编造代码**。用户"优化释放上下文资源（变量/缓存/会话）"指令实为对话上下文释放诉求，对应本归档动作。
- **原文定位**：`02-Areas-资产/九思-机制库/运维与恢复/2026-08-22-投稿稿-Hy3限免撞墙429踩坑记录.md`
