## 一、知识库架构（Vault 结构）

胡子哥的 Obsidian vault 由 6 个核心目录构成，比喻成一条认知生产线。

### 目录结构

```
Obsidian Vault 根目录/
├─ 00 - 灵感库/        ← 所有新灵感先放这，待处理
│  ├─ index/           ← 目录索引
│  └─ （灵感文件）
├─ 01 - 项目/          ← 正在做的具体项目（有明确截止日期）
│  ├─ 工薪族财富创造方法论/
│  └─ 知识卡片研究/
├─ 02 - 长期关注/      ← 真正的复利资产，可以自我运转
│  ├─ AI / 财富变现 / 投资 / 认知基础 / 内容创作 / 个人品牌
├─ 03 - 参考资料/      ← 外部信息源、浮墨（flomo）素材
├─ 04 - 归档/          ← 已完成/搁置的项目（30天自动清理）
├─ 05 - Skills/        ← 自己写的脚本和程序（全是自写，不用外部的）
├─ 06 - Wikis/         ← 自动抽取的关键概念库
│  ├─ 176 个经典概念，跨越 22 个学科
│  └─ 目前 121+ 个关键概念，持续增加
```

### 每目录详解

**00 - 灵感库**：所有新灵感先进来。最新写的自我反思、认知记录都先放这里。分类：外部输入（读书/深度视频）、发散方式（模糊念头）、解决问题（日常遇到的具体问题）。

**01 - 项目**：当前明确在做的具体项目，只有目录。如果东西少了，说明最近没干什么"实事"。胡子哥有洁癖——以前的好东西能删全删掉。

**02 - 长期关注**：这才是真正的资产，可以自我运转。直播间大家关注的是 01 项目区，但其实 02 才是真正的大头。包含他反向工程爱马仕的自我进化结构。

**03 - 参考资料**：网上的好东西拿过来存。所有"浮墨（flomo）"碎片素材从这来。

**04 - 归档**：归档 ≠ 垃圾桶。设了 30 天期限，30 天没拿走就自动删除。

**05 - Skills**：全是自己写的自动化脚本，不用外边人写的。功能：做索引、做向量相互连接、做双链、搜索知识库、自动构建知识图谱、增量提取关键概念。

**06 - Wikis**：176 个经典概念跨越 22 个学科，不是手动添加，是从知识卡片自动抽取的。每个概念都有来源链接。

## 二、AI 如何理解你的知识库

### AI 天生能识别什么
AI 天生能识别 Markdown 格式（标题 #、加粗 **、列表 - 等）和 JSON 格式。Obsidian 的 .md 文件本身就是 Markdown。

### 目录授权（实操中最关键、最多人出错的地方）
核心原则：**不是把整个系统给 AI，而是只授权一个工作目录。**

```bash
cd /path/to/your/vault
# 在这个目录下打开 AI 工具（Cursor、Claude Code 均可）
```

最常见的错误：很多人直接在根目录下打开 AI 工具，结果权限受限，然后觉得工具不好用。

### 引导文件
胡子哥在知识库里写了一个引导文件，内容包括：你的名字、核心目录、每个目录的用途、为什么这样设计、你的工作流程。

使用方法："请帮我理解一下这个文件"→ AI 就认识你的整个知识库了。

### 本地大模型配置策略

**温度调参表：**
| 温度 | 效果 | 用途 |
|:--|:--|:--|
| 0.4 | 稳定精准 | 常规任务 |
| 0.6 | 开始飘 | 需要一点创意 |
| 0.7 | 天马行空 | 胡子哥的创意模型 |
| 0.8 | 高度随机 | 极少使用 |

胡子哥刻意把创意模型设在 0.7："很多人把幻觉当做弱项，但我特别喜欢那种幻觉。我负责稳固，我希望天马行空的东西。"

**大小模型配合策略：**
每个大模型配一个小模型，流程：任务进来 → 小模型先解构 → 不合适直接退回 → 合适把结构化结果扔给大模型 → 大模型只处理精加工部分。

胡子哥的模型分工：
- 读文件/常规处理 → 小模型（千问 9B，中文理解深）
- 复杂任务 → 大模型
- 创意/灵感 → Google 模型（温度 0.7）
- 写程序 → Claude Code
- 脏活累活 → QCloud（免费 API 额度多，"生产队的驴"）

## 三、认知生产管线（核心工作流）

### 完整流程图

```
① 灵感/洞见（读书/视频/日常思考/问题）
    ↓ 写成知识卡片
② 知识卡片放入库
    ↓ AI 自动分析、抽取
③ 抽取关键概念 → 写入 Wiki 库（增量更新）
    ↓ AI 搜索：这个人早就总结过了！
④ 匹配已有概念（设计模式、控制论、同群效应…）
    ↓ 概念碰撞（向量相似度 0.6-0.75）
⑤ 产生新认知/新洞见
    ↓ 注卡（经审核）
⑥ 新的知识卡片，回到 ②
```

### AI 自动抽取关键概念
当天写的《流量规模等于身份维护》→ AI 提取：
1. 认知带宽（新增）
2. 挤出效应（新增）
3. 防御性注意（新增）
Wiki 库从 118 个→121 个关键概念。

### 连接已有知识（源于"设计模式"顿悟）
胡子哥自学程序，自己琢磨出"解决问题的方法"，两三年后看到《设计模式》，发现人家早就总结好了 23 种模式。从此决定：以后任何知识卡片都用 AI 抽，抽完了去世界上找——还有哪些东西是人家早就搞明白的？

对比 Roam Research：Roam 自动生成双向链接但太乱。胡子哥的做法——只抽取核心的东西，不要多，要精。

### 概念碰撞（认知匕首 3.0 / Cognitive Dagger）

工作原理：
1. 从 Wiki 库取一个关键概念（如：控制环悖论）
2. 从灵感库取当前素材（如：身份维护）
3. 计算向量相似度（阈值 0.6-0.75）——有一定关联但不完全相同
4. 产生新的认知洞见
5. 评估：可注卡、可升华、可反馈

**碰撞示例：**「身份维护」×「控制环悖论」→ "如果执行层面过度占用了控制层的带宽，控制就会丧失动机，导致系统失去和现实的价值连接"

经典比喻："这就好像一条狗被主人养了，汪汪两声主人就摸摸头给好吃的。它觉得很爽，学会了更好地汪汪。但它已经不是狼了。"

## 四、直播即兴认知产出

### 内容深度检查机制
胡子哥写在系统里的（不是记在脑子里，是可运行的代码）：
- 写了文章/视频脚本 → 扔到系统里
- AI 自动检查内容的深度
- 太肤浅 → 系统告警："对不起，你拍的这个视频内容太肤浅了"
- 成了他的防御系统

### 真进化 vs 伪成熟
公式：**进化 = 摩擦 + 痛苦后的喜悦**
- 总是很舒服 → 没有在进化 → 只是在享受之前系统的红利
- 成熟 ≠ 进化（成熟让你越来越舒服，进化让你突破）

### 认知势能
大部分钱来自于认知势能。水往下流，认知势能下去就一定能产生能量或赚到钱。
维护认知势能的两种方式：①提升自己的认知（学者/创作者）②利用大众媒体找到认知势能比你低的人（知识博主）

### 你与 AI 的真正关系

| 角色 | 功能 |
|:--|:--|
| 秘书 | 日常处理 |
| 朋友 | 共同讨论 |
| 老师 | 给建议 |
| 同学 | 一起学习 |
| 知己 | 理解你的知识体系 |
| 对手 | 给你反馈、挑战你 |

## 五、工具选择

AI 工具三件套：
- **Claude Code** — 主力（写程序）
- **Cursor** — 实验性（内容处理，崩了无所谓）
- **QCloud** — "牛马"（脏活累活，免费 API 用起来不心疼）

### 给新手的严肃建议
**不要一上来就复制整套系统！** 先用一个简单的 AI 工具用 2-3 周，搞明白了再换。

"提示词拿给你们一点用都没有。我的提示词是完整的、是我自己的。你拿过去相当于用别人的架构跑你的东西。"

## 七、实验者心态

胡子哥认为自己的身份是：**测试者**。

"我以前是敏捷软件开发程序员。有新东西就快速尝试或试错→错误反馈告诉我什么不可行→加以改进。"

关键方法：每次只控制一个变量。失败了成本很小，基本盘是 OK 的。

注卡标准：所有卡片要经过审核流程，有标准的三审六部去审核。AI 不是随便帮你怎么做都可以的——你还得听它的。

## 八、核心金句

> "我十年前就明白了：每天做一件小事，在原有的基础上果断地迭代。意义就会变得很强大。"

> "我的知识全是可以运行的。我们真正要做的是——反复做有用的东西，简化、简化、再简化，把能量集中在最重要的事情上。"

> "不要指望一堂课把所有的知识都记住。学东西是——哪个东西能用，先让它能使用起来。然后再慢慢学。"

> "AI 有我知识库里所有的东西。每次交流我的知识他全知道，且下次再来的时候是升级的。"

> "进化不是让你越来越舒服。如果你总是很舒服，意味着你没有进化，你是躺在以前的系统里面享受之前的红利。"

> "我从来不缺灵感。因为我的知识是螺旋式的不断增长，建立在你以往的知识基础上，不断地迭代和增长。"

## 九、行动指南

### 新手最小可执行步骤
1. 搭建基础目录：灵感→项目→长期→参考→归档（5个就行）
2. 写一个引导文件：告诉 AI 你的目录结构
3. 每天写一张知识卡片
4. 选一个 AI 工具先用上 2-3 周
5. 让 AI 帮你抽取概念
6. 慢慢迭代

### 进阶路线
1. 建立向量数据库，让概念之间可以智能碰撞
2. 写自己的 Skills，自动化日常处理
3. 建立 RSS 信息流
4. 建立内容深度检查机制
5. 把系统当做一个"可进化的生命体"

---

> **一句话总结：知识库的结构就是你的生产线。让 AI 理解你的目录结构，每天在原有基础上迭代，不要每次都从零开始。**
