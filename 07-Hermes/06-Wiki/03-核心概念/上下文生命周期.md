# 上下文生命周期

> 2026-08-02 沉淀（源自压缩中断问题诊断 + 用户高维构想）

## 核心洞察

上下文（context）不是"用完就忘"的临时空间，而是有生命周期的**可回收资产**：

```
产生（对话）→ 沉淀（分流）→ 进化（提炼）→ 固化（存OB）→ 释放（压缩）→ 循环
```

## 关键认知

1. **上下文窗口是模型硬限制（100万），但有效记忆是无限的**——通过外部沉淀+按需检索
2. **对话的价值分四类**：内容型（进OB）/ 经验型（进观察池）/ 战略型（进方向）/ 临时型（删）
3. **沉淀是"复制价值"，不是"删除对话"**——清理必须用户确认
4. **压缩不是故障，是保护机制**——会话到阈值自动摘要，释放空间继续用

## 落地机制

- context_check cron（每日扫窗口活跃tokens，超52万提醒沉淀）
- context-sedimentation Skill（沉淀执行器：三问分流）
- 观察池 v2（承接经验/战略输入）
- 压缩配置：threshold 0.65 / target 0.35 / protect 50
