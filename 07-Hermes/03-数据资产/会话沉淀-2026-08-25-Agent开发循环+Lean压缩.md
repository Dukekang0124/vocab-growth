## 核心成果

### 1. Hermes上下文压缩机制全调研（08-25）

**调研过程**：查阅官方文档+GitHub Issue #17251，发现：
- 默认 `legacy` 模式 = LLM摘要中间轮次，有损
- `lean` 模式 = 确定性锚点提取（正则抓PR/SHA/路径/错误串）**不 paraphrase** + 所有用户消息原样引用 + `session_search` recovery pointer
- **GitHub #17251 bug**：compaction 后 handoff 把 MEMORY 降级为 "background reference, NOT active instructions"，Agent 字面执行 → 重启后忽略记忆

**已落地**：
- ✅ config `compression.tail_mode: legacy → lean`（一行生效，已重启验证）
- ✅ MEMORY.md 加压缩防御提醒（重启后主动读 MEMORY/SOUL 重新注入）
- ✅ 规则总库 #16 登记（Lean模式机制 + #17251 风险）
- ✅ 省钱机制第6条铁律：善用上下文压缩，但知道省钱大头是缓存命中

### 2. Agent开发循环 Skill 建立（08-25）

**来源**：小红书「非也Origin」笔记——"Agent写完还要一遍遍检查？先写清完成标准，再让Agent自动开发、检查、修复，直到达标。"

**三步循环**：
```
① 立标准（可验证二值判断）→ ② 开发循环（开发→自检→修复→循环到达标）→ ③ 独立复核（换视角扫一遍）
```

**关键约束**：自检必须**输出📋清单给用户看**（不是心里想）；❌必须修不能跳过；循环超3次停下来重评估标准。

**已落地**：
- ✅ 新建 Skill：`hermes-operations/agent-dev-loop/SKILL.md`
- ✅ 规则总库 #17 登记
- ✅ 机制触发地图加2行（场景表+高频表）
- ✅ **task-commander 执行层强制**：第③步加 "有完成标准的任务→每步用agent-dev-loop自检"
- ✅ 变更台账 + 状态日志登记

### 3. 全流程重新闭环（08-25）

**暴露的问题**：第一轮工作时凭感觉说"完成了"，没有逐条输出📋自检清单，状态日志还有重复行。

**第二次用dev-loop重跑**：10项标准全部✅通过，独立复核发现并修复了状态日志重复行。

**真实学会的标志**：不是建了Skill文件，而是下一次有完成标准的任务时，我会**自动输出📋清单逐条过✅/❌**，不凭感觉说完成。
