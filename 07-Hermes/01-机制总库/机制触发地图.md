# 🗺 机制触发地图（场景→机制 速查）

> 2026-08-20 建立。机制建了很多，但「什么场景启动什么」必须清晰，否则今天建A明天忘B。
> 用法：**接任何任务，先看这个表，找到当前场景，启动对应机制**。不靠记性，靠地图。
> 判断标准：用户说「今天建了A忘了B」= 没看地图 = 记忆混乱。

---

## 场景 → 机制 映射表

| 场景 | 必须启动的机制 | 一句话 |
|:--|:--|:--|
| **接任何任务** | 先查后做完整闭环 | 先查OB/Session/Skill/观察池，命中复用不重造 |
| **分析选题** | 选题前置（查选题总库）+ 曝光潜力第一关 + 8分制 | 先查有没有，再判曝光潜力 |
| **写脚本** | 🧪**叙事驱动**（困境叙事>干货）+ 查证清单（查4文件+3问）+ 表达框架库 | 主角是「困境里的我」不是「方法」；输出📋查证清单；AI能写的公式/步骤降级 |
| **写脚本后** | 反向验证3问 + 活人感5条自查 + **双置顶评论** + 手动commit | 验证规避了没、活人感用出来没、双置顶给了没、commit做基准线 |
| **审稿** | 审稿前diff识别用户改动 + 36+2维 + 🆕hook-writer-sms / optimization-advisor-sms | 先diff看用户改了啥，活人感保留；钩子重写用hook-writer，数据优化用optimization-advisor |
| **分析作品** | 发布时间判断（数据成熟度）+ 五层漏斗 + 假设驱动 + 深度分析5查 + 问题反哺作品问题库 + 🆕content-pattern-analyzer-sms / performance-analyzer-sms | 先看发了多久，再看漏斗，问题记作品问题库；类型分析+数据复盘用新技能 |
| **分析账号** | 12维 + 假设驱动（不平均用力） | 定位异常维度，假设+验证 |
| **发布** | 阶段零（拍完标✅）+ 阶段一（先读排版规范）+ 阶段二（归档四步） | 拍完标✅，排版先读规范，发完归档 |
| **拍完** | 选题总库标✅ | 第一件事，别忘 |
| **重要任务收尾** | 收尾四查（沉淀/固化/合并/最后一环） | 输出四查清单给用户看 |
| **任何有完成标准的产出任务**（写代码/脚本/配置/Skill/文档/报告） | **agent-dev-loop**（先立标准→开发自检循环→独立复核） | 不凭感觉说完成；输出📋清单逐项过✅/❌；❌必须修 |
| **沉淀** | 沉淀四查（进OB/进化系统/Skill/固化） | 沉淀了没落位=白沉淀 |
| **建cron** | 确认repeat=forever + 手动触发验证 | 别建了跑一次就停 |
| **改共享资源** | 变更影响检查（查引用/更新台账/状态日志） | 改完查引用，不断裂 |
| **读书/消化内容** | 消化罗盘四问 + 沉淀OB | 内容发来就消化，不等提醒 |
| **外部对标学习** | 提取内容→深度拆解（结构/手法/母题）→提炼可迁移动作+新母题→沉淀学习库+红线卡绿灯 | 用户发外部博主作品链接，说「深度学习/拆解/以后也这么做」 |
| **解决难题** | 沉淀自觉（高耗时/反复坑/配置变更/用户纠正） | 解决了就沉淀，不等提醒 |
| **用户纠正我** | 反思根因 + 更新SOUL/记忆/机制 | 纠正=机制有漏洞，修根因 |

## 高频场景 → 机制（最常忘的，标红）

| 最容易忘的 | 触发 |
|:--|:--|
| 🔴 **拍完标✅** | 用户说「拍完了」→ 选题总库标✅（第一件事，不是分析数据） |
| 🔴 **写脚本前查证** | 写脚本 → 先输出📋查证清单（查4文件+3问，不是直接写） |
| 🔴 **分析看发布时间** | 分析作品 → 先看发了多久（<4h不下结论） |
| 🔴 **写脚本用活人感** | 写脚本 → 主动用啊/呢/咱，不是等用户改 |
|| 🔴 **收尾四查** | 任务收尾 → 输出四查清单（不是心里想） |
|| 🔴 **agent-dev-loop** | 有完成标准的任务 → 先输出📋清单（逐条✅/❌），不达标必须修，不凭感觉说完成 |
| 🔴 **写完后双置顶** | 写完脚本 → 必带①橱窗引流+②引发评论（别忘了） |
| 🔴 **写完后手动commit** | 写完脚本 → 立即commit「九思写的版本」（diff学习基准线） |
| 🔴 **发布后归档** | 发布完 → 归档四步（删桌面图+更新状态看板） |
| 🔴 **分析后记问题库** | 分析作品发现新问题 → 记作品问题库（否则下次还犯） |
| 🔴 **选题先查系统** | 分析/策划选题 → 先查千万别系列/选题库/评论区池/已发布（别重复做） |

> 完整内容创作闭环（选题→写前→写中→写后→审稿→发布→复盘）见：`自媒体系统/苏不倦自媒体方法论/内容创作/内容创作机制速查.md`

## 元规则（所有机制之上）

```
① 机制执行 = 可验证的输出（不靠自觉，输出清单给用户看）
② 建了机制 ≠ 执行机制（写了≠做了，输出=证据）
③ 老靠用户提醒反问 = 自我进化失败
```
