# 变更台账并发写入规范

> 2026-08-06 确立（解决多窗口并发写覆盖问题）。
> 背景：⑪号写入台账时覆盖了⑥号的"卖铲子"条目（并发写同一文件=后写覆盖先写）。

## 问题根因

- 变更台账.md 是**共享文件**（所有窗口读）
- 但**多个窗口同时写**（⑪号写+⑥号写）→ 后写入的覆盖先写入的

## 解决规范（写前必读）

### 1. 写台账前必须重读（硬规则）

**任何窗口写变更台账前，先 read_file 确认最新内容**（文件可能被其他窗口刚改过）——用最新的"表头行"做锚点，不凭记忆的旧内容。

```python
# 正确（写前重读）
content = read_file("变更台账.md")  # 先读最新
patch(old=最新表头, new=新条目+最新表头)  # 基于最新改

# 错误（凭旧内容覆盖）
patch(old=旧表头, new=新条目+旧表头)  # 旧锚点可能已被别人改
```

### 2. 写后立即验证（防静默覆盖）

写完台账后，**grep 确认自己的条目还在**（`grep 关键词 变更台账.md`）——如果不见了，说明并发冲突，立即补回。

### 3. 高并发时段避免

**同一时间只允许一个窗口写台账**——如果检测到别的窗口正在写（文件修改时间<1分钟前），**等待或稍后再写**。

### 4. 终极方案（后续实施）

各窗口写**自己的变更记录文件**（如 `07-Hermes/变更台账-⑪号.md`），⑨号总长**定期汇总**到主台账——**彻底消除并发写**。当前先执行 1-3（写前重读+写后验证+错峰）。

## 为什么这样能解决

- **写前重读**：保证锚点是最新的（不覆盖别人的）
- **写后验证**：发现覆盖立即补（不静默丢失）
- **错峰**：减少并发窗口（降低冲突概率）
- **分区**（终极）：物理上隔离（彻底解决）

## 触发

- 任何窗口写变更台账/状态日志/观察池（所有共享流水账文件）
- 用户说"台账怎么又覆盖了"→ 提醒按本规范操作
