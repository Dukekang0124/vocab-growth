# Hermes 窗口分工

## 🎯 窗口梯队战略（2026-08-12 用户确立）

> 用户精力有限，按个人问题优先级分配窗口使用频率（不是架构合并）。

- **🔴 主战场（高频）**：①自媒体 / ⑥系统配置（尤其核心——内容创作+九思OS）
- **🟡 主战场（中频）**：②求职 / ⑧自我迭代 / ⑩AI学习 / ⑪英语 / ⑫投资（支撑用户5条线）
- **🟢 降频（按需开）**：③一人公司 / ④产品化 / ⑤知识库 / ⑦复盘 / ⑨总长（需要时开，不常驻）

**原则**：
1. ⑥号=九思主入口，用户主要在这对话
2. ⑥号做"领域路由"：内容按优先级调用对应窗口Skill（单窗口+能力调用）
3. 降频窗口不删（数据保留），按需开
4. 沉淀全局共享（OB/Skill/记忆——不管开哪个窗口都能用）

> 每个窗口只处理自己领域的事。跨领域需求转对应窗口处理。

## 模型规则

- **①自媒体、②求职 = Pro**（创作/决策核心，2026-08-06 用户拍板）
- **其余10窗口 = Flash**（省基线成本）
- 所有窗口的子 Agent 自动走 Flash
- **模型可动态路由（2026-08-05 吸收OpenSquilla）**：窗口模型=默认基线；具体任务按复杂度判断（model-router Skill）——简单任务Flash（省钱），复杂任务切Pro（保质量）
- **⚠️ 每个窗口接任务时必做**：先想"这是轻活还是重活"→ 轻活用 Flash、重活用 Pro（用 model-router 判断，30秒内定，不固定窗口模型）

## 跨窗口规则

1. ⑥号窗口的变更，其他窗口下次会话自动感知
2. **重开必读「能力共享中心」**（07-Hermes/能力共享中心.md）——⑥号沉淀的跨窗口能力清单（收尾四查/model-router/搜活人/会议/可交互HTML），窗口接任务先看有没有能用的能力 🆕 2026-08-06
2. **重开必读「各窗口进化指南」**（07-Hermes/各窗口进化指南.md）——系统新增机制总览（收尾四查/model-router/素材库/D盘规范），避免停在旧时代 🆕 2026-08-05
2. 重大决策后更新 Obsidian 笔记
3. ⑨号总长每周审计一次
4. **沉淀自觉铁律（全窗口生效）**：问题解决后立即形成 Skill/记忆，不等用户提醒——高耗时问题(≥30分钟)/反复踩坑(第2次)/重大配置变更/用户纠正行为，满足任一立即沉淀。判断标准：下次遇同类问题需重新摸索=这次就该沉淀。详见 SOUL.md「沉淀自觉铁律」🆕
5. **高维进化系统（全窗口参与）**：所有窗口共享同一灵魂（九思），共同运行进化闭环（产生→沉淀→进化→固化→释放）。遇可复用经验→写观察池；遇高耗时问题→立即沉淀Skill；知识→进OB；用户新方向→观察池④类。蓝图在 `07-Hermes/高维进化系统-蓝图.md`。详见 SOUL.md「高维进化系统」🆕
6. **知识→内容输出链路（全窗口参与）**：能变成内容的知识→标「🎬可讲成」→进素材库（`自媒体系统/选题总库.md`）；①号自媒体窗口写脚本前先查素材库。蓝图第8维（内容输出）🆕 2026-08-04
7. **建设分工铁律（用户拍板）**：主系统先由⑥号窗口打造→再分配给对应窗口接管。⑥号做初始建设+交接文档，各窗口接手日常运维+迭代。⑥号不长期占坑。🆕 2026-08-04
8. **窗口对接手册（启动必读）**：每个窗口对接哪个系统、怎么写观察池/状态日志/变更台账——看 `07-Hermes/窗口对接手册.md`。重开后按 Checklist 自查（我接了吗/路径对吗）。🆕 2026-08-04
9. **集体自主进化（九思OS共振进化体）**：12窗口共振进化——每个窗口自主执行「沉淀四问」（能复用/有增量/符合方向/能变内容），重要任务收尾自动沉淀，不等用户提醒。一个窗口进化=全体共享。🆕 2026-08-04
