# 🧭 九思OS 系统盘点与内容分流指南

> 2026-08-04 建立（用户"系统越高层越容易跑偏"担忧 → 系统性治理）。
> 目的：①盘点所有系统/能力/技能/文档的对应关系 ②内容进来时**按规则分流**，不靠感觉 ③防止窗口环路/重复建设/最后一环验证出错。
> 核心：**每个内容只能进一个"主管系统"，由主管系统决定去向——不能多系统争抢。**

## 三、内容分流规则（核心！谁主管，进谁的系统）

> **原则：一份内容 = 一个主管系统。先判"它解决什么问题"，再定主管，由主管决定去向。**

### 分流判据（第一层：内容类型）

| 内容类型 | 判据 | 主管系统 | 去向 |
|:--|:--|:--|:--|
| **知识型** | 讲"是什么/为什么"（概念/认知/方法论）| 知识系统⑤ | 06-Wiki 概念库 → 标「可讲成」→ 素材库 |
| **经验型** | 讲"怎么做的"（踩坑/流程/教训）| 高维进化⑥ | 观察池 → 周提炼 → Skill |
| **行动型** | 讲"该做什么"（练手/盘点/计划）| 行动系统⑧ | sell-while-learning → 技能盘点 |
| **赚钱型** | 讲"怎么变现"（商业模式/定价）| 变现系统③ | 犯错者红利/靠近收入创造 → 素材库 |
| **内容型** | 讲"怎么讲"（脚本/选题/表达）| 内容系统① | 素材库 → topic-selection |
| **求职型** | 讲"怎么找工作" | 求职系统② | 投递手册/简历 |
| **工具型** | 讲"什么工具好用" | 系统配置⑥ | community-tool-evaluation → 装/不装 |
| **临时型** | 一次性/无关 | —— | 删，不进任何系统 |

### 分流判据（第二层：交叉时怎么办）

| 冲突场景 | 规则 |
|:--|:--|
| 内容同时是"知识+能讲成内容" | **先进知识系统⑤**（沉淀为概念），再标「可讲成」→ 内容系统①消费 |
| 内容同时是"经验+方法论" | **先进观察池⑥**（经验），成熟后提炼成 Skill/概念 |
| 用户发的方向/构想 | 观察池④类（战略观察），⑧号战略参谋决策 |
| 不确定归哪 | 默认进**观察池⑥**（宁沉淀不错放），⑥号周提炼时再分流 |

### 防环路铁律 🆕
1. **一份内容只进一个系统**，不允许 A→B→A 循环（防止 token 空转）
2. **概念→素材库是单向**（知识系统产概念，内容系统消费），**不允许内容系统反过来建概念**（回灌要走评论区新问题通道）
3. **所有吸收的内容，最终要能回答"它进哪个系统了"**——说不出的=没沉淀（沉淀自觉铁律）

---

## 四、为什么这样能防跑偏

| 风险 | 怎么防 |
|:--|:--|
| 内容乱进系统 | 分流判据固定（类型→主管→去向）|
| 窗口环路 | 一份内容一个主管，防 A→B→A |
| 重复建设 | 系统盘点表一眼看到"已有"，先查再建 |
| 最后一环验证出错 | 变更必须登记台账+影响检查（已有机制）|
| 小失误搞垮大系统 | 单点改动只影响对应系统，不跨系统（依赖索引管控）|

---

## 五、使用方式

- **每个窗口**：遇到新内容 → 先看分流判据 → 判定主管系统 → 按去向处理
- **⑥号**：负责维护本指南（系统盘点/分流规则随系统生长更新）
- **⑨号总长审计**：检查有没有"内容进错系统/窗口环路"（审计项）
